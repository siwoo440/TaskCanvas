# TaskCanvas 최신 개발 일정 — 30~78일차 재배치

> **최신 기준: 2026-10-20. 상태: 30~31일차 업로드·매핑·검증·저장 구현, 32~78일차 계획.** 1~29일차 과거 구현 기록은 유지한다. [30일차 구현·검증](30-file-preview.md)을 추가했으며 이 문서는 이후 개발의 **우선 적용 일정**이다. 이전 `docs/10-wbs-timeline.md`의 30~52일차 순번과 Google 통합 문서의 이전 53~78일차 순번은 **기획 변경 전 기록**이며 아래 최신 번호를 우선한다. 개발 일차는 달력상의 날짜나 실제 소요 기간이 아니다.

## 1. 변경 핵심

- **30~63일차:** 데이터 관리·협업·보드·분할 UI·오피스 파일 편집 및 내보내기를 먼저 구현한다. 네트워크 외부 서비스 연결 없이도 내부 기능을 사용할 수 있어야 한다.
- **64~68일차:** 파일 손상·원본 유실·권한 우회·저장 실패를 막는 **필수 안전장치를 개발한다.** 이것은 나중으로 미룰 수 없는 기능 개발이며 최종 종합 테스트와 구별한다.
- **69~73일차:** 공공데이터 API, Google Drive OAuth, 외부 문서 임베드 등 **외부 서비스/API 연동을 마지막 개발 단계에 집중한다.** 해당 서비스 이용 승인/요금/프레임 정책에 따라 지원 범위를 줄일 수 있다.
- **74~78일차:** 오피스 왕복 호환성, 보안·장애·기존 기능 회귀, 학교 PC 4대 LAN 검증 및 제출 자료 갱신 등 **최종 종합 테스트를 맨 마지막에 수행한다.**
- **안전 예외:** 각 개발 일차의 단위·스모크·권한·무결성 확인은 구현 직후 지속한다. 이를 74일차까지 생략하면 저장 손상과 누적 결함 위험이 크다. 최종 인수/통합 테스트의 일정만 뒤로 모은다.
- **공공데이터 API 없을 때:** 30~35일차 내부 CSV·JSON/업무 데이터로 차트와 필터를 사용할 수 있고, 최종 시연에서는 외부 API 실패 시 마지막 정상 데이터·로컬 파일 가져오기를 제공한다.

## 3. 변경 영향 및 기존 기획과 관계

- 30일차부터 개발 일차 번호를 새로 부여하므로 과거 문서의 ‘31일차 공공 API’, ‘34일차 학교 LAN 최종 검증’, ‘52일차 확장 테스트’, ‘57/70/78일차 최종 테스트’ 등은 **이 문서의 일정으로 대체된다**. 기능의 삭제나 완료 선언이 아니다.
- E01~E14는 기능 식별자 그대로, E15(분할 화면), E16(오피스 편집·내보내기), E17(안정화)는 범위를 유지한 채 번호만 변경했다. 29일차 기본 필터 등 이미 구현된 기능은 다시 신규 작업으로 세지 않는다.
- E15 외부 임베드는 69일차로 분리하고 51~53일차에는 외부 API 없는 분할 UI만 만든다. E16 파일 편집·다운로드는 54~63일차, 외부 Google Drive 직접 저장은 71일차에 연동한다.
- 기존 문서들에 남은 과거 일차별 설명은 **변경 전 계획 기록**이다. 새 개발 커밋·README 및 보고서는 이 문서의 새 번호를 기준으로 작성한다.
- 목표는 테스트 오류 0을 **보장**하는 것이 아니라 테스트 기준을 충족하지 못한 형식·기능을 실제 출시하지 않는 것이다. 현장 LAN 테스트는 실제 PC로 직접 수행해야 하며 자동화 브라우저 4개로 대신할 수 없다.

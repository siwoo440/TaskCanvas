# 29일차 — KPI·차트·업무 표 분석 대시보드

구현·검증 기간: 2026-10-18~19. 28일차 통계 API를 유지하면서 실제 DB 업무를 조회하는 분석 화면을 추가했다. DB 마이그레이션은 없다.

---
## 사용 방법

1. 회원 또는 게스트로 작업실에 입장한다.
2. 작업실 제목 옆 **분석 대시보드**를 누른다. 열람자·편집자·관리자 모두 조회 가능하다.
3. 기본 최근 30일의 업무를 확인한다. 생성일·상태·담당자를 바꾼 뒤 **조회**를 누르면 모든 지표와 목록에 같은 조건이 적용된다.
4. **이전·다음**으로 20건씩 이동한다. **새로고침**은 마지막으로 요청한 조건을 다시 조회한다. 입력만 바꾸고 조회하지 않았다면 변경 전 적용 조건을 사용한다.
5. **작업실로 돌아가기**로 보드·업무 현황판에 복귀한다. 분석 화면을 닫으면 결과와 조건을 폐기하며 다음 진입은 기본 30일이다.

## 표시 항목

| 영역 | 의미 |
| --- | --- |
| 전체 업무 | 선택 조건에 해당하는 업무 원본 수 |
| 업무 완료율 | 완료 업무 / 전체 업무, 소수 첫째 자리 |
| 마감 초과 | 서울 기준 오늘 이전에 마감된 미완료 업무 |
| 체크리스트 완료율 | 완료 항목 / 전체 항목, 소수 첫째 자리 |
| 상태 도넛 | 할 일·진행 중·완료·기존 기타 상태 분포 |
| 담당자 막대 | 담당자별 전체·완료 수, 동명 담당자도 ID로 구분, 미배정 별도 |
| 일별 생성 수 | 선택 기간에 생성된 업무 수, 빈 날짜는 0건 |
| 업무 표 | 제목·상태·담당자·마감·생성일·체크리스트 진행률 |

여러 보드가 같은 업무를 참조해도 한 건으로 집계한다. 분모가 0이면 완료율은 0%다. 선 그래프는 생성 수이며 과거 완료율이나 업무 변경 이력을 뜻하지 않는다.

## API 계약

`GET /api/projects/{id}/analytics/dashboard` — 기존 게스트 인증과 viewer 이상 작업실 권한 필요, Cache-Control: no-store.

| 조건 | 규칙 |
| --- | --- |
| created_from·created_to | 실제 존재하는 1000~9999년 YYYY-MM-DD, 양끝 포함 |
| 둘 다 생략 | 서울 오늘-29일 ~ 오늘 |
| 시작일만 | 입력 시작일 ~ 서울 오늘 |
| 종료일만 | 입력 종료일-29일 ~ 입력 종료일 |
| 기간 길이 | 1~366일, 역순·범위 이탈은 400 |
| status | 생략=전체, todo·doing·done |
| assignee_id | 생략=전체, 양의 정수 ID 또는 unassigned |
| page | 생략=1, PHP 정수 범위의 정규 양의 정수 |

빈 값·배열·알 수 없는 키도 INVALID_FILTER 400이다. 화면의 전체 선택은 쿼리에서 생략한다. 페이지 크기는 20으로 고정하며 생성일·task_id 내림차순이다. 범위 초과 페이지는 마지막으로 보정한다. 빈 결과는 1/1페이지, total=0, rows=[]다.

| 응답 필드 | 내용 |
| --- | --- |
| project_id·time_zone·as_of_date | 작업실·Asia/Seoul·마감 기준일 |
| filters | 기본값을 적용한 날짜·상태·담당자 |
| summary | 28일차와 같은 tasks·assignees·due·checklist 구조 |
| daily_created | date·count, 날짜 오름차순과 빈 날짜 포함 |
| assignee_options | 작업실 멤버와 기존 업무 담당자의 assignee_id·display_name |
| pagination | page·page_size·total·total_pages |
| rows | 현재 페이지 업무의 task_id·title·status·assignee_id·assignee_name·due_at·created_at·checklist |

rows.checklist는 total·done·completion_rate다. 업무 설명과 항목별 제목은 반환하지 않는다. 미배정 ID·이름과 없는 마감은 null이다. 시각 문자열은 기존 DB의 서울 현지 시각 의미를 따른다. 담당자 선택지는 조회 조건과 독립적이며 다른 작업실 정보는 포함하지 않는다.

## 일관성과 화면 보호

- 같은 PDO 연결의 REPEATABLE READ 읽기 전용 스냅샷으로 요약·추이·표·선택지를 조회한다. 성공 시 종료하고 오류 시 롤백한다.
- 서울 기준일을 요청당 한 번 계산하여 자정 경계에서도 기본 기간과 마감 분류가 일치한다.
- 공통 필터 검증과 SQL 조건은 기존 summary와 재사용한다. summary의 날짜 생략 의미는 변경하지 않는다.
- 새 조회 시 이전 결과를 비우고, 작업실·요청 세대가 일치하는 응답만 표시한다. 이전 성공·실패가 현재 화면에 영향을 주지 않는다.
- 화면 이탈·작업실 전환·로그아웃·인증 만료 시 결과·담당자 목록·차트 인스턴스를 폐기한다. 기존 실시간 인증·작업실 삭제 통지도 유지한다.
- 로딩·입력 오류·통신 오류·빈 결과를 표시한다. 차트 파일 실패 시 KPI와 대체 데이터 표를 유지한다.
- Chart.js 4.5.1 MIT 원본을 로컬 배포한다. 버전·출처·해시는 [배포물 기록](../apps/frontend/public/lib/chartjs/SOURCE.md), 라이선스는 같은 폴더 LICENSE.md에 있다. CDN 요청은 없다.
- 차트별 데이터 표·입력 이름·포커스 표시를 제공한다. 360px에서는 세로 배치하고 업무 표 안에서만 가로 스크롤한다.

신규 PHP 검증은 프로젝트 루트에서 `C:\xampp\php\php.exe -d zend.assertions=1 -d assert.exception=1 apps/php-api/tests/analytics-snapshot.php`와 같은 방식으로 실행한다. Node 검증은 `node apps/realtime/scripts/test-dashboard.js` 또는 해당 파일 경로로 실행한다. 테스트는 고유 DB·예약 포트·서버 식별로 개발 환경과 분리한다.

독립 검토에서 발견한 9999년 날짜 상한 반복 문제는 실제 HTTP 실패 재현 후 DateTime 객체 비교로 수정하고 재검토를 통과했다. 초기 스냅샷 테스트에서 설정 재로드 누락으로 생성된 개발 DB의 고유 테스트 작업실 2개·업무 2개는 확인 후 제거했다. 이후 쓰기 전 SELECT DATABASE() 확인을 추가했고 기존 사용자 데이터는 변경하지 않았다.

## 남은 범위

학교 PC 4대 AC15와 별도 입력 방식의 현장 검증은 미실행 상태다. 실시간 이벤트에 따른 분석 자동 갱신, 저장 뷰, 차트 드릴다운, CSV·JSON 가져오기, 공공데이터, 업무 변경 이력은 후속 일정이다. 현재 분석은 새로고침으로 최신 저장 상태를 반영한다.

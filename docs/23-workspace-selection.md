# 23일차 — 참여 중인 작업실 전환 (1차 구현)

## 목표

현재 게스트가 이미 소속된 작업실이 2개 이상이면 작업실 화면에 전환 선택지를 표시한다. 전환 목록은 서버의 `GET /api/me` 응답에 포함된 `projects` 배열만 사용한다.

이 구현은 **같은 게스트 계정에 여러 작업실의 멤버십이 실제로 존재하는 경우**를 위한 UI 1차 단계다. 새로운 작업실에 현재 세션을 유지하면서 추가 가입하거나 다른 게스트의 세션으로 바꾸는 기능은 아직 지원하지 않는다. 기존 PHP 세션·초대 검증을 변경하지 않았다.

## 사용 방법 (Usage)

1. `GET /api/me` 응답에 동일 `guest_id`의 참여 작업실이 2개 이상 존재하면 작업실 화면의 '작업실 전환'이 보인다.
2. 다른 작업실을 고르면 현재 작업실의 실시간 연결을 끊고, 이전 보드·참여자·업무 상태를 비운 뒤 선택한 작업실의 데이터를 다시 조회한다.
3. 선택 작업실 번호는 현재 브라우저 탭의 `sessionStorage`에 기록한다. 새로고침하면 서버가 그 작업실 멤버십을 다시 확인한 다음 복원한다.
4. 서버가 선택 권한을 주지 않거나 작업실이 삭제되었으면 기록을 신뢰하지 않고 접근 가능한 첫 작업실로 복귀한다.
5. 새 작업실 생성이나 초대 코드 입장 시에는 새로 받은 `project_id`가 이전 선택 기록보다 우선한다.

## 보호 규칙

- 초대 코드·쿠키 토큰·재입장 코드는 `sessionStorage`에 저장하지 않는다. 오직 프로젝트 숫자 ID만 기록한다.
- 재입장용 '내 코드'를 아직 보관하지 않았거나 대화상자가 열려 있으면 작업실을 전환하지 않는다.
- 작업실을 나가거나 삭제 알림으로 퇴장하면 저장된 선택 번호와 기존 목록을 지운다.
- PHP API와 Socket.IO의 기존 프로젝트별 권한 검증을 그대로 사용한다.
- **현재 세션이 한 작업실에만 속한 일반적인 사용자는 전환 UI가 보이지 않는다.** 향후 추가 가입 흐름을 별도로 설계한다.

## 테스트

단위 테스트: `node --test apps/realtime/scripts/workspace-selection.test.cjs`

검증 항목: 첫 작업실 기본 선택, 현재 탭 선택 복원, 신규 입장 우선 선택, 임의 번호 거부, 빈 멤버십, 문자열 입력 거부.

수동 통합 테스트(학교 PC·DB 필요):
1. 테스트 전용 게스트 하나를 **별도 테스트 DB에서** 두 개 작업실의 `project_members`에 안전하게 등록한다.
2. `GET /api/me`에 두 작업실이 나타나는지 확인한다.
3. 작업실 A에서 B로 전환한 뒤 보드·업무가 서로 섞이지 않는지 확인한다.
4. F5 후 B가 선택되고 A의 이전 커서·연결이 남지 않는지 확인한다.
5. 로그아웃과 삭제 후에도 이전 작업실 정보가 누출되지 않는지 확인한다.

운영 DB에 직접 테스트 데이터 삽입 금지. 실환경 AC15는 여전히 별도의 현장 검증 대상이다.

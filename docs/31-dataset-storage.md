# 31일차 — 컬럼 매핑·전체 검증·데이터셋 저장

2026-10-20. 기존에 승인한 파일 가져오기 상세 설계·직접 구현 계획의 저장 단계를 최신 31일차 일정으로 진행했다. 30일차의 원본 업로드·미리보기를 확장하며, 기존 업무·보드 데이터와 별도로 저장한다.

---
## 1. 사용 순서

1. 작업실 → 데이터 관리 → CSV·JSON 가져오기.
2. 파일 선택 → 파일 업로드. 중첩 JSON은 안내된 JSON Pointer 경로를 입력하고 원본 다시 읽기.
3. 데이터셋 이름과 컬럼 이름·문자/숫자/날짜/제외·필수 여부를 설정.
4. 중복을 식별할 키 컬럼 하나와 건너뛰기/갱신 정책 선택. 키 없는 신규 저장도 가능.
5. 전체 행 검증 → 오류가 0일 때 DB에 저장.
6. 저장 목록·페이지당20행 표·기본 막대차트·가져오기 이력 재조회. 브라우저 새로고침 뒤에도 목록에서 다시 선택 가능.

기존 데이터셋은 ‘이 자료에 재가져오기’에서 기존 컬럼에 원본 열을 연결한다. 기존 스키마·필수 여부·키는 변경할 수 없다. 키 없는 데이터셋은 신규 저장만 지원한다. 파일에 없는 기존 행을 자동 삭제하지 않는다.

---
## 2. 값과 중복 규칙

| 항목 | 규칙 |
| --- | --- |
| 문자 | 원문 공백·대소문자 보존, HTML은 텍스트로 표시, 최대4,000자 |
| 빈 값 | null·빈 문자열·공백만 있는 값은 결측 처리. 필수이면 오류, 선택이면 null |
| 숫자 | 앞뒤 공백 제거, 정수부12자리·소수6자리, 지수/통화/천단위 쉼표 거부 |
| 숫자 저장 | 반올림 없는 정규화10진 문자열. `001.230000`→`1.23`, 음수0→`0` |
| 날짜 | 앞뒤 공백 제거, 실제 존재하는1000~9999년 `YYYY-MM-DD`, 형식 추측 없음 |
| 키 | 포함한 컬럼 하나, 자동 필수. 문자 키는 원문, 숫자·날짜는 정규화 값 |
| 건너뛰기 | 파일 안 첫 행 채택, 기존 동일 키 행 유지 |
| 갱신 | 파일 안 마지막 행 채택, 기존 동일 키의 값 교체·저장 row_id 유지 |

전체 원본을 검증하며 오류 하나라도 있으면 전체 저장을 차단한다. 오류 행을 조용히 제외하지 않는다. 오류 위치는 원본 데이터 행·필드·사유이며 목록은 첫100건, 전체 오류 수는 별도로 반환한다. 이 검증은 저장 안전장치이며 32일차의 독립 품질 보고서 완료를 의미하지 않는다.

파일5MiB·10,000행·50열·초안15분 제한은30일차와 동일하다. 확정 데이터셋 최대10,000행, 작업실 최대100개 데이터셋·100,000행이다. 한도 초과 시 기존 자료를 삭제하지 않는다.

## 3. 저장 안전성과 권한

- 관리자·편집자: 업로드·검증·신규 저장·재가져오기. 열람자: 저장 목록·표·집계·이력 조회. 관리자: 이름 재입력과 버전 확인 후 삭제.
- 검증 결과는 서버의 초안·매핑·검증 revision에 결합한다. 저장은 토큰과 revision만 받고 클라이언트가 보낸 행은 거부한다.
- 저장 시 원본을 다시 파싱하고 세션·역할·대상 version·용량을 재검사한다. 프로젝트→세션→초안→데이터셋 순서로 잠근다.
- 데이터셋·행·성공 이력·초안 소비를 하나의 트랜잭션으로 확정한다. 실패하면 전체 롤백한다.
- 같은 초안의 동시 저장과 응답 유실 재시도는 동일 결과를 반환한다. 성공 후 원본 조각은 삭제하고 결과는24시간 재응답 가능하다.
- 조건 변경 시 이전 검증을 폐기한다. 저장 중 조작은 잠그며, 화면/신원 변경 이후 늦은 응답은 무시한다. 만료·손상 초안의 원본·정규화 보고서도 제거한다.
- 다른 탭 로그아웃의 비활성 DOM 즉시 삭제는 지원하지 않는다. 기존 계정 이벤트·서버 인증 오류·탭 복귀 재인증에서 정리한다.

## 4. API

모든 경로는 `/api/projects/{id}` 아래이며, POST는 `X-TaskCanvas: 1`이 필요하다. 인증·권한을 입력 해석 전에 확인한다. 응답은 no-store다.

| 경로 | 권한 | 입력·결과 |
| --- | --- | --- |
| POST `/imports/validate` | editor | draft_token·mode·columns·duplicate_policy, 신규 name/key_column 또는 merge target_dataset_id/expected_version → validation_revision·schema·report·첫20행 |
| POST `/imports/commit` | editor | draft_token·validation_revision → dataset_id·version·row_count·inserted/updated/skipped·run_id |
| GET `/datasets` | viewer | q·page →20건 목록·페이지 |
| GET `/datasets/{datasetId}` | viewer | 저장 스키마·키·버전·행 수 |
| GET `/datasets/{datasetId}/rows` | viewer | page →20행 표와 같은 스냅샷의 데이터셋 |
| GET `/datasets/{datasetId}/chart` | viewer | category·metric=count/sum·value →정확한 문자열 합계·범주별 표 |
| GET `/datasets/{datasetId}/runs` | viewer | page →선택 자료 이력 |
| GET `/imports/runs` | viewer | page →작업실 전체 이력 |
| POST `/datasets/{datasetId}/delete` | admin | confirm_name·expected_version →대상 자료만 삭제 |

신규 columns는 source_id·label·type(text/number/date/exclude)·required, merge columns는 기존 id·source_id 목록이다. 키는 신규 저장 필드 순서의 c0·c1 등이다. 알 수 없는 필드·잘못된 형식400, 권한401/403, 대상 없음404, 오래된 revision/version409, 초안 만료410, 용량413, 오류 자료 확정422다.

기본 차트는 저장 확인용 건수·숫자 합계다. DECIMAL로 합산하고 `0.1+0.2`는 문자열 `0.3`으로 반환한다. 최대19개 범주+나머지 묶음이며 null·실제 같은 이름의 값·합성 묶음을 구분한다. 차트 라이브러리가 없어도 정확 수치 표를 제공한다. 고급 대시보드 필터·저장 뷰는 후속 범위다.

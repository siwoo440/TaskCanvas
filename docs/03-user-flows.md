# 사용자 흐름 및 시나리오

---

## 일반 게스트 입장

1. 서버 주소(학교 PC LAN IP)에 접속.
2. 화면에서 표시 이름과 초대 코드를 입력.
3. PHP API가 초대 코드 해시·유효기간·사용 권한을 검사.
4. 서버가 게스트 ID와 프로젝트 멤버십/세션을 생성하고 안전한 쿠키를 발급.
5. 최초 진입 시 프로젝트의 기본 보드를 열고 저장된 객체를 불러옴.
6. 프론트엔드가 단기 실시간 연결 티켓을 받아 Socket.IO로 보드에 참여.

---

## 동시 필기와 저장

1. 게스트 A가 펜 도구를 선택하고 마우스를 누름.
2. 브라우저가 `stroke:preview`를 제한된 빈도로 전송.
3. 서버가 같은 보드의 게스트 B/C/D에게 미리보기 전달.
4. 마우스를 놓으면 `stroke:commit`을 전송하고, 서버가 DB에 저장.
5. 저장 성공 응답과 최종 획 ID를 받고 저장 상태를 갱신.
6. 재접속 시 DB의 최신 보드 스냅샷으로 완성된 획을 다시 그림.

---

## 도형 선점 잠금

1. 사용자 A가 객체를 선택하여 이동하려고 시도.
2. `object:lock` 요청. 서버가 권한 및 기존 잠금 여부 검사.
3. 획득에 성공하면 A에게 토큰·만료 시간을 회신하고 다른 사용자 화면에 잠금 표시.
4. A는 이동 중 `object:preview`, 놓으면 `object:commit` 전송.
5. 서버가 잠금 소유 및 버전 검사 뒤 저장하고 잠금 해제.
6. A의 연결이 끊어지거나 TTL이 만료되면 서버가 잠금을 해제.

---

## 공유 업무(P1)

1. 기획 보드와 개발 보드 각각에 `object_id`가 다른 업무 블럭 생성.
2. 두 블럭 모두 `task_id=101`을 참조.
3. 한 보드에서 상태를 변경하면 공유된 업무 원본을 업데이트하고 관련 보드에 전파.
4. 한 보드의 블럭 삭제는 `board_objects` 행만 제거하고 `tasks` 원본은 보존.

---

## 연결 해제

- **완료·저장된** 객체만 보존됨.
- 미완성 획·확정되지 않은 이동 등은 복원하지 않음.
- 재접속 시 화면 상태를 초기화하고 서버의 최신 저장 상태를 불러옴.
- 사용자에게 연결 복구 및 복원 기준을 명확하게 표시.

# 사용자 흐름 및 시나리오

구현된 동작 기준입니다(16단계). 이벤트 이름과 응답 형식은 [HTTP API](07-http-api.md)와 [실시간 계약](08-realtime-contract.md)을 따릅니다.

---

## 일반 게스트 입장

1. 서버 주소(학교 PC LAN IP)에 접속하면 소개 페이지가 열림. 초대 링크(`…/#code=코드`)로 열면 소개를 건너뛰고 코드가 채워진 입장 화면이 열림.
2. 입장 화면에서 표시 이름과 초대 코드를 입력.
3. PHP API가 초대 코드 해시·유효기간·취소 여부를 검사. 인원 제한이 있는 코드는 새 참여자일 때만 남은 인원을 확인.
4. 서버가 게스트와 프로젝트 멤버십, 세션을 만들고 HttpOnly 쿠키를 발급. 같은 프로젝트에 같은 이름으로 다시 들어오면 기존 참여자와 역할을 그대로 씀.
5. 같은 홈 화면이 작업실로 바뀌어 보드 목록·업무 현황판·참여자가 보임. 관리자에게는 초대 코드 관리가 함께 보임. 작업실도 작업실용 티켓으로 실시간 서버에 연결되어, 현황판이 보드에서 일어난 업무 변경을 바로 보여 줌.
6. 보드를 고르면 저장된 객체를 불러오고, 단기 실시간 접속 티켓을 받아 Socket.IO 로 보드에 참여.
7. 보드를 보다가 새로고침하면 작업실을 거치지 않고 보던 보드와 위치로 돌아옴.

## 초대 코드 발급 (관리자)

1. 프로젝트를 만들 때 CLI 가 관리자 초대 코드를 한 번 출력. 그 코드로 입장한 사람이 관리자가 됨.
2. 관리자는 작업실에서 역할(편집자·열람자·관리자), 유효 기간(1~30일), 인원 제한(비우면 제한 없음)을 골라 코드를 발급.
3. 코드 원문과 초대 링크는 발급 직후에만 화면에 보임. DB 에는 해시만 남음.
4. 목록에서 역할·만료·입장 인원·상태를 보고 코드를 취소할 수 있음. 취소해도 이미 입장한 사람은 유지됨.

## 동시 필기와 저장

1. 게스트 A가 펜 도구를 선택하고 마우스를 누름.
2. 브라우저가 `stroke:preview`를 약 40ms 간격으로 전송.
3. 서버가 같은 보드의 게스트 B/C/D에게 미리보기 전달. DB 에는 쓰지 않음.
4. 마우스를 놓으면 `stroke:commit`을 전송하고, 서버가 DB에 저장.
5. 저장 성공 응답과 최종 획 ID를 받고 저장 상태를 `저장됨` 으로 바꿈.
6. 새로고침·재접속 시 DB의 최신 보드 스냅샷으로 완성된 획을 다시 그림.

## 도형 선점 잠금

1. 사용자 A가 객체를 선택하여 이동하려고 시도.
2. `object:lock` 요청. 서버가 권한 및 기존 잠금 여부 검사.
3. 획득에 성공하면 A에게 토큰·만료 시간을 회신하고 다른 사용자 화면에 "A 편집 중" 표시.
4. A는 이동 중 `object:preview`, 놓으면 `object:commit` 전송.
5. 서버가 잠금 소유 및 버전 검사 뒤 저장하고 잠금 해제. 버전이 다르면 `VERSION_CONFLICT` 로 거부.
6. A의 연결이 끊어지거나 30초 동안 갱신이 없으면 서버가 잠금을 해제.

## 실행 취소와 다시 실행

1. 사용자가 만들기·옮기기·크기·스타일·메모 글·삭제·연결선 작업을 하면 브라우저가 "되돌릴 때 보낼 값"을 최대 50개 기억.
2. Ctrl+Z 를 누르면 가장 최근 작업을 기존 이벤트(`object:commit`·`object:delete`·`object:create` 등)로 되돌리고, 그 반대 작업을 다시 실행 기록에 쌓음.
3. Ctrl+Y(또는 Ctrl+Shift+Z)를 누르면 방금 되돌린 작업을 다시 적용.
4. 내 작업 뒤에 다른 사람이 고쳤거나 잡고 있는 객체는 건드리지 않고 안내만 함.
5. 새 작업을 하면 다시 실행 기록은 비워짐. 보드를 바꾸거나 재접속하면 두 기록 모두 비워짐.

## 공유 업무(P1)

1. 기획 보드와 개발 보드 각각에 `object_id`가 다른 업무 블럭 생성.
2. 두 블럭 모두 같은 `task_id`를 참조.
3. 한 보드에서 상태를 변경하면 공유된 업무 원본을 업데이트하고, 그 프로젝트의 어느 보드를 보고 있든 모든 참여자에게 전파.
4. 한 보드의 블럭 삭제는 `board_objects` 행만 제거하고 `tasks` 원본은 보존.
5. 작업실의 업무 현황판은 프로젝트의 모든 업무를 할 일·진행 중·완료 세 열로 보여 줌. 보드에 놓지 않은 업무도 보임.
6. 편집자 이상은 카드를 다른 열에 끌어 놓아 상태를 바꾸고, 카드를 눌러 제목·담당자·마감일을 고치고, **새 업무**로 업무를 만듦. 보드의 같은 업무 블럭에 바로 반영.
7. 대화상자를 연 사이에 다른 사람이 같은 업무를 바꿨으면 덮어쓰지 않고 최신 내용으로 다시 채워 확인하게 함.
8. 마감이 지났거나 3일 안으로 다가온 업무는 카드와 블럭에 색으로 표시(지남은 빨강, 오늘·임박은 주황). 완료한 업무는 표시하지 않음.
9. 열람자, 그리고 실시간 서버에 연결되지 않은 화면은 현황판을 볼 수만 있음.

---

## 연결 해제

- **완료·저장된** 객체만 보존됨.
- 미완성 획·확정되지 않은 이동 등은 복원하지 않음.
- 재접속 시 화면 상태를 초기화하고 서버의 최신 저장 상태를 불러옴.
- 상단에 `연결됨`·`재접속 중`·`연결 끊김` 을 표시하고, 재접속되면 마지막 저장 상태를 불러왔다고 안내함.
- 실시간 서버에 한 번도 연결되지 못하면 접속 점검 화면(`/check.html`)을 열어 보라고 안내함.

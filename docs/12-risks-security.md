## 보안 체크리스트

구현과 대조한 결과입니다(9단계에 처음 대조, 16단계 2026-10-10 에 현재 코드로 다시 대조, 17단계의 작업실 연결 반영). 괄호 안은 근거 위치입니다.

- [x] 세션/초대 코드는 난수 기반으로 생성하고 해시만 저장. (`Auth::newSecret` 의 `random_bytes`, `Invite::generateCode` 의 `random_int`, DB 에는 SHA-256 해시만. 초대 목록 API 도 원문·해시를 반환하지 않음 — AC20)
- [x] 프로젝트 멤버십·역할을 모든 HTTP/Socket 수정 요청에서 재검사. (HTTP 는 `Auth::requireRole`, Socket 은 확정·생성·잠금·삭제·업무·연결선 이벤트마다 `auth.hasRole` 로 DB 재조회 — AC14)
- [x] `board_id`가 현재 게스트 프로젝트에 속하는지 확인. (티켓이 보드에 묶이고, 소켓은 참여한 보드와 다른 `board_id` 이벤트를 거부 — AC02. 작업실용 티켓은 프로젝트에만 묶여 보드 방에 들어갈 수 없고, 그 연결이 보내는 보드 이벤트는 모두 거부 — AC26)
- [x] 파일이 이미지인지 서버 측에서 검사, 10MB 제한. (`finfo` 내용 MIME + `getimagesize` — AC08·AC09)
- [x] 업로드 저장 경로는 웹 문서 루트 밖, 파일 직접 실행 금지. (`apps/php-api/storage/uploads`, 랜덤 파일명·고정 확장자, `storage/.htaccess` 로 직접 접근 차단, 조회는 `/api/images/{id}` 만)
- [x] PHP SQL은 PDO 바인딩, HTML 텍스트는 출력 이스케이프. (모든 쿼리 `Database::run` 바인딩. 프론트엔드는 서버 값을 `textContent`·캔버스 `fillText` 로만 표시하고 `innerHTML` 에는 고정 문자열만 사용)
- [x] CSRF 방어 및 세션 쿠키 HttpOnly / SameSite / HTTPS에서 Secure. (`X-TaskCanvas` 헤더 검사, `SameSite=Strict`·`HttpOnly`, `COOKIE_SECURE=1` 로 Secure)
- [x] 실시간 서버는 자기와 같은 호스트에서 열린 페이지의 연결만 허용. (`CORS_ORIGIN=auto` 기본값, 웹소켓을 포함한 모든 새 연결에서 Origin 헤더 검사 — SEC01, 14단계)
- [x] 외부 영상은 허용된 서비스의 안전한 임베드 URL만 사용. (서버 `video.js` 가 YouTube·Vimeo ID 를 검사해 임베드 URL 을 직접 생성, iframe `sandbox` — AC11)
- [x] 저장·삭제·잠금은 서버 권한·버전·소유자 검증. (잠금 토큰·`version` 비교·`SELECT … FOR UPDATE` — AC06·AC07·AC19)
- [x] `.env`, 실제 초대 코드, 학교 PC IP·비공개 자료, 데이터베이스 덤프 업로드 금지. (`.gitignore` 로 `.env`·업로드·덤프 제외. 저장소에는 `.env.example` 과 `schema.sql` 만 있음)

### 알고 있는 한계 (시연 범위에서 수용)

- 학교 LAN 시연은 HTTP 입니다. 같은 네트워크에서 트래픽을 볼 수 있는 사람은 세션 쿠키와 초대 코드를 볼 수 있으므로 공개망에 그대로 올리지 않습니다.
- 초대 링크(`#code=…`)는 서버 로그에는 남지 않지만(# 뒤는 전송되지 않음) 링크를 전달한 메신저·화면에는 남습니다. 입장 직후 주소창에서는 지워집니다. 시연이 끝나면 관리자 화면에서 코드를 취소합니다.
- 실시간 서버의 접속 출처 검사는 브라우저가 보내는 Origin 헤더를 봅니다. 다른 사이트의 페이지가 붙는 것은 막지만, 브라우저가 아닌 프로그램은 이 헤더를 마음대로 보낼 수 있습니다. 실제 권한은 여전히 일회용 티켓이 지킵니다.
- 요청 제한은 입장(`/api/guest/join`)에만 있습니다. 실시간 이벤트는 커서(약 30Hz)와 이벤트 크기(1MB)만 제한합니다.
- 초대 코드의 인원 제한은 선택 사항입니다. 비워 두고 발급한 코드는 만료·취소 전까지 여러 명이 쓸 수 있으므로 시연이 끝나면 취소합니다.
- 보드에서 지운 이미지의 파일은 정리 스크립트(`clean-uploads.php`)를 돌리기 전까지 서버에 남습니다. 실행 취소로 되살릴 수 있게 하려는 것이며, 그 이미지의 주소는 같은 프로젝트 참여자만 열 수 있습니다.
- 새로고침 복원을 위해 브라우저의 `sessionStorage` 에 보드 번호와 화면 위치를 적어 둡니다. 탭마다 따로이고 초대 코드·세션 값은 넣지 않습니다.
- 접속 점검 화면(`/check.html`), `/api/health`, 실시간 서버의 `/health` 와 `net:ping` 은 입장하지 않아도 응답합니다. 서버가 켜져 있는지와 DB 연결 여부만 알려 주고 보드 내용은 다루지 않습니다.
- 작업실의 업무 현황판은 실시간 서버에 연결되어야 업무를 만들고 바꿀 수 있습니다. 연결되지 않으면 보기만 됩니다. 업무 원본을 지우는 기능은 없으므로 잘못 만든 업무는 제목을 고치거나 완료로 옮겨 정리합니다.
- 마감 표시(지남·임박)는 화면을 보는 PC 의 날짜로 계산합니다. PC 의 날짜가 틀리면 표시가 달라집니다.

## 실패 시 축소 기준

| 시점 | 실패 기준 | 대응 |
|---|---|---|
| 1주 종료 | 2인 펜 동기화 실패 | 미디어·업무 개발보다 실시간 연결 해결 우선 |
| 2주 종료 | 4인 편집·저장·복원 실패 | P1 중단, P0 안정화 |
| 최종 주 후반 | 주요 오류 잔존 | 새 기능 중단, 시연 범위 고정 |

지연은 리허설 스크립트(`npm run rehearsal`)가 잽니다. 개발 PC 1대 안에서 브라우저 네 개로 잰 값(2026-10-08)은 미리보기 전달 중앙값 약 1ms, 확정 저장 응답 중앙값 3~6ms 였습니다. 통과 기준은 미리보기 150ms·확정 저장 500ms 로 넉넉하게 잡았습니다(제안값, [미정 사항](14-open-decisions.md) 참고). 이 측정에는 LAN 구간이 들어 있지 않으므로 학교 PC 에서는 선이 눈으로 보기에 바로 따라오는지를 함께 확인합니다. 접속 PC 마다의 실시간 왕복 시간은 접속 점검 화면(`/check.html`)이 보여 줍니다.

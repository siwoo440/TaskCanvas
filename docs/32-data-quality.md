# 32일차 — 데이터 품질 검사·오류 보고서

2026-10-20. CSV·JSON 전체 검증의 품질 요약과 상세 문제 행을 보관하고, 검사 예상치와 실제 저장 건수를 대조한다. 31일차의 오류 시 전체 저장 차단·키 중복 정책·원자적 저장을 유지한다.

---
## 1. 사용 흐름

1. 작업실 → 데이터 관리 → CSV·JSON 가져오기 → 파일 업로드.
2. 컬럼 이름·문자/숫자/날짜·필수 여부·키·중복 정책을 지정하고 전체 행 검증.
3. 데이터 품질 요약에서 수신·정상·오류 행, 오류·경고 개수, 컬럼별 결측·결측률·형식 오류 확인.
4. ‘전체 품질 보고서 보기’에서 심각도·문제 유형·컬럼을 선택하고 문제 행 조회. 문제 행20개 단위로 이동.
5. 오류가 있으면 파일을 수정해 다시 업로드·검증. 현재 파일/매핑/정책을 바꾸면 이전 저장 자격과 현재 상세 보고서를 폐기.
6. 오류0일 때 저장. 성공 후 보고서에서 예상/실제 건수와 저장 전후 행 수 대조.
7. 새로고침 후 저장 데이터를 선택하고 가져오기 이력의 ‘품질 보고서’ 버튼으로 당시 기록 재조회. 저장 전 오류 이력은 ‘작업실 전체 이력’에서 조회.

과거 보고서는 당시 파일·매핑·정책·대상 버전의 기록이다. 현재 데이터를 다시 검사한 결과가 아니다. 파일 원문 자동 수정이나 오류 행 자동 제외는 하지 않는다.

---
## 2. 수치와 오류·경고

| 항목 | 기준 |
| --- | --- |
| 오류 행 | 저장 차단 오류가 하나 이상 있는 서로 다른 원본 데이터 행 |
| 오류 개수 | 한 행의 여러 문제를 각각 계산. 오류3개가 오류 행2개에 속할 수 있음 |
| 정상 행 | 수신−오류 행. 정책에 따라 건너뛰는 정상 중복 행 포함 |
| 결측 | 포함 컬럼의 원본 null·빈 문자열·공백만 있는 값. 숫자 변환 실패는 결측 아님 |
| 결측률 | 컬럼 결측/수신×100, 소수 첫째 자리. 빈 분모0 |
| 저장 차단 오류 | 필수 결측·숫자·날짜·셀 자료형/길이·원본 행 구조 |
| 경고 | 선택 컬럼 결측·파일 안 중복·기존 자료 중복. 정책대로 저장 가능 |
| 파일 안 중복 | 형식 검증을 통과한 키의 두 번째 이후 행 |
| 기존 중복 | 정상 키가 대상 데이터셋에 존재하는 행 |
| 중복 행 | 위 두 집합의 합집합. 개별 건수를 단순 합산하지 않음 |

키 없음에서는 중복을 임의 판정하지 않는다. 문자 공백/대소문자·숫자 정밀도·날짜 규칙은31일차와 동일하다. 구조 오류가 있는 셀의 파서 null을 정상 빈 값으로 집계하지 않는다. 제외 컬럼은 값 품질 통계에서 제외하되 파일 구조/용량 제한은 유지한다.

상세 필터는 같은 행에서 조건에 맞는 문제 항목만 표시한다. 한 행에 여러 항목이 있어도 페이지 건수는 한 행이다. 키 중복은 ‘행 구조/중복’ 컬럼 그룹으로 표시한다. 저장 직전 오류 목록의 첫100건 제한과 별개로 보고서에는 전체 문제 행이 보관된다.

## 3. 저장 결과 대조와 보관

검사 예상치와 실제 확정치를 별도 열로 표시한다. 검증 완료·저장 실패·버전 충돌 상태의 실제값은 미확정이며0으로 가장하지 않는다.

성공 시 수신=신규+갱신+건너뛰기, 저장 후 행 수=저장 전 행 수+신규, 예상=실제 여부를 확인한다. 갱신은 기존 row_id를 유지하고 전체 행 수를 늘리지 않는다. 보고서 확정 기록이 실패하면 데이터·version·이력·초안 소비도 함께 롤백된다. 같은 초안의 동시 저장과 응답 유실 재시도는 동일 보고서·결과를 사용한다.

보고서는 기존 import_runs에 종속된 import_quality_reports와 문제 행별 import_quality_rows에 보관한다. 초안 만료·성공 후 원본 삭제와 별도 수명이며, 이력/데이터셋/작업실 삭제 시 FK로 정리된다. 새 기능 이전 이력에는 보고서가 없을 수 있고 이 경우 ‘상세 품질 보고서 없음’을 표시한다. 과거 자료를 추정해 생성하지 않는다.

보고서에는 원문 셀·키 값·파일 바이트·세션 토큰을 복제하지 않는다. 검사 조건·컬럼 메타데이터·문제 코드/위치·수치만 보관한다. 문제 행별 작은 JSON으로 기록하며 DB 전역 패킷 설정을 바꾸지 않는다. 원본5MiB·10,000행·50열·초안15분·기존 데이터셋 한도는 유지한다.

## 4. API와 권한

POST `/api/projects/{id}/imports/validate`의 기존 응답에 run_id·quality 요약을 추가한다. 기존 revision·report·정규화 미리보기 계약은 유지한다. editor 이상과 변경 보호 헤더가 필요하다.

| 조회 경로 | 입력·결과 |
| --- | --- |
| GET `/api/projects/{id}/imports/runs/{runId}/quality` | 당시 파일·조건·schema·checked_at·status·summary·expected·actual·comparison |
| GET `/api/projects/{id}/imports/runs/{runId}/quality/rows` | page·severity·type·column 교집합, rows와 pagination |

viewer 이상이 조회할 수 있으며 회원 연결 세션은 회원 쿠키도 필요하다. 작업실·run 소유 범위를 확인하고 응답은no-store다. 없는/다른 작업실/구형 보고서는 QUALITY_REPORT_NOT_FOUND404, 잘못된·배열형·불명 필터는400이다. 초안 토큰은 URL에 넣지 않는다.

- severity: error 또는 warning, 생략하면 전체.
- type: required_missing·invalid_number·invalid_date·invalid_cell·invalid_row·optional_missing·duplicate_file·duplicate_existing.
- column: 당시 포함 컬럼의 source_id 또는 `__row__`(행 구조/중복).
- page: 정규 양의 정수, 기본1·행20개. 큰 번호는 마지막 페이지, 빈 결과1/1.

summary는 received·valid_rows·error_rows·error_count·warning_rows·warning_count·duplicate_rows·file_duplicate_rows·existing_duplicate_rows·columns다. actual/comparison은 성공 전null이다. 상세 rows는 source_row와 조건에 맞는 issues(severity·type·source_id·field·message)를 제공한다.

## 5. 검증 기록과 남은 범위

- 품질 스키마29개·품질 집계28개·실제 품질 API51개 통과. 기존 가져오기 스키마는 신규 품질 표를 포함해47개, 파서49개 통과.
- 실제 API에서10,000행×50열 오류500,000개·문제 행10,000개 기록, 각 행 JSON이1MiB보다 작은 것 확인. 첫100건 이후120행/6페이지, 복합 필터·중첩 중복·권한·초안 수명·구형 이력·두 서버 멱등 저장·보고서 SQL 오류 전체 롤백 검사.
- 실제 CUA에서 오류3/오류행2, 결측25%, 경고 복합 필터,120행 페이지 이동, 파일 변경 시 이전 보고서 폐기 확인. 수정 파일은 신규3·건너뛰기1로 저장되고 새로고침 후 이력에서 예상/실제 일치 확인.
- 모바일360px에서 문서 폭/스크롤345px, 보고서 표 영역285px 내부 스크롤540/450px. 문서 전체 가로 넘침 없음.
- 개발 DB 전체 백업88,846바이트, 기존22개 표 전체 행 해시 동일, 품질 표2개 추가.
- 기존 저장91·업로드35·통계40·대시보드41·회원인증41·회원접근59, PHP 기존 검사·화면 VM·인증 가드·포트 보호·작업실 선택/하단7개 통과. 분리 DB 수용 자동28·보안2·운영1 통과, 수동2 유지.

다른 탭 로그아웃의 비활성 DOM 즉시 삭제는 기존처럼 지원하지 않는다. 탭 복귀·계정 이벤트·서버 인증 오류에서 정리한다. 고급 대시보드 필터는 압축 33일차, 학교 PC 4대 AC15는 압축 40일차 현장 검증 범위다.

재실행: `php apps/php-api/tests/import-quality-schema.php`, `import-quality-scan.php`, `node apps/realtime/scripts/test-import-quality.js`, `test-import-quality-client.js`. DB 검사는 고유 테스트 DB를 생성·정리하고 개발 DB를 초기화하지 않는다.

독립 최종 검토에서 구조 오류의 합성 null이 필수 결측으로 중복 보고되는 문제를 발견해 수정했다. 비객체 JSON·필수 배열/제어 문자 셀과 CSV의 실제 빈 셀/누락 열을 구분하는 회귀를 추가했다. 고유 브라우저 검증 회원·작업실27·데이터셋1개/3행은 소유 식별자 확인 후 정리했다.

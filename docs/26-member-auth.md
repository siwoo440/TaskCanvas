# 26일차 — 회원 인증 API와 화면

홈 상단 **입장하기 오른쪽 로그인**에서 `/login.html`로 이동합니다. 로그인 화면의 회원가입 링크는 `/register.html`로 연결됩니다. 가입 완료 후 로그인 화면으로, 로그인 완료 후 홈으로 이동하여 회원 이름과 로그아웃 버튼을 표시합니다. 기존 게스트 입장·작업실 생성은 별도 기능으로 유지합니다.

회원가입의 비밀번호·비밀번호 확인 오른쪽 눈 버튼은 누르는 동안만 해당 입력을 표시합니다. 마우스·터치 또는 Space·Enter 키를 놓으면 다시 숨기며, 초점 이탈·탭 전환·페이지 이동·양식 제출 때도 숨김 상태로 복구합니다. 실제 브라우저에서 마우스 누름·해제와 Space 누름·해제를 확인했습니다.

## 입력과 응답

| API | 요청 | 성공 응답 |
|---|---|---|
| `POST /api/auth/register` | `login_id`, `display_name`, `password`, `password_confirm` | 201 `{user}`. 자동 로그인하지 않고 로그인 화면으로 안내 |
| `POST /api/auth/login` | `login_id`, `password` | 200 `{user}`와 HttpOnly 회원 쿠키 |
| `GET /api/auth/me` | 회원 쿠키 | 200 `{user}`, 세션 없음·만료·폐기는 401 |
| `POST /api/auth/logout` | 회원 쿠키와 빈 JSON 객체 | 200 `{logged_out: true}`, 현재 브라우저의 회원 세션 폐기 |

회원 응답은 `user_id`, `login_id`, `display_name`, `created_at`만 포함합니다. 변경 요청은 기존 `X-TaskCanvas: 1` 헤더가 필요합니다. API 응답은 `Cache-Control: no-store`입니다.

- 로그인 ID: 영문·숫자로 시작하는 3~40자의 영문·숫자·점·밑줄·하이픈. 앞뒤 공백 제거와 소문자 통일 후 저장. 중복 ID는 409 `LOGIN_ID_TAKEN`.
- 표시 이름: 앞뒤 공백 제거 후 1~60자. 제어 문자 거부, 화면에서는 `textContent`로 표시.
- 가입 비밀번호: 8글자 이상, UTF-8 최대 72바이트, NUL 금지. 확인 입력과 일치 필수. 앞뒤 공백을 보존하며 평문을 DB·URL·브라우저 저장소에 저장하지 않음.
- 입력 오류는 400, ID·비밀번호 불일치는 동일한 401 `INVALID_CREDENTIALS`. 없는 회원도 더미 해시 검사.

## 세션과 요청 보호

`USER_SESSION_COOKIE` 기본값은 `tc_user_session`, `USER_SESSION_TTL`은 기본 43200초입니다. 기존 `.env`에 새 항목이 없어도 기본값으로 동작합니다. 회원과 게스트 쿠키 이름을 같게 지정하면 세션 덮어쓰기를 막기 위해 오류로 처리합니다.

24바이트 난수 토큰을 쿠키로 전달하고 SHA-256 해시만 `user_sessions`에 저장합니다. 쿠키는 `HttpOnly`, `SameSite=Strict`, `Path=/`이며 HTTPS 배포는 기존 `COOKIE_SECURE=1` 설정을 사용합니다. 재로그인 시 현재 브라우저의 이전 세션을 폐기하고 새 토큰을 발급하며 다른 브라우저 세션은 유지합니다. 로그아웃은 서버 `revoked_at`과 쿠키 만료를 함께 처리합니다.

회원가입·로그인은 기존 `join_attempts`·`RATE_LIMIT`·`RATE_WINDOW`의 IP별 제한을 게스트 입장·작업실 생성과 공유합니다. 잘못된 입력도 해시 검사 전에 기록합니다. 기본 설정은 같은 IP에서 10분 동안 합계 20회이며 초과 시 429입니다.

## 회원과 게스트의 경계

회원가입·로그인은 `guest_user_links`·게스트·멤버십을 생성하거나 이전하지 않습니다. `/api/auth/me`는 회원, `/api/me`는 게스트 상태입니다. 두 쿠키는 공존하며 회원 로그아웃은 게스트 세션을 지우지 않습니다. 회원 로그인만으로 기존 작업실 접근 권한을 부여하지 않습니다.

게스트 소유 확인과 회원 연결, 초대 재입장 보호, Socket.IO 인증 연계는 [25일차 설계](25-member-data.md)의 27일차 범위입니다. 비밀번호 찾기·이메일 인증·계정 삭제도 이번 범위에 없습니다.

## 검증과 실행

```powershell
node apps/realtime/scripts/test-member-auth.js # 분리된 DB와 PHP 서버의 인증 검사
node apps/realtime/scripts/test-auth-port-safety.js # 점유된 포트의 기존 서버 변경 차단
& 'C:\xampp\php\php.exe' apps/php-api/tests/env.php # 설정 파일 없는 환경의 DB 설정 격리
& 'C:\xampp\php\php.exe' apps/php-api/tests/member-schema.php # 기존 회원 스키마 회귀
```

인증 검사는 임의의 `taskcanvas_d26_` DB와 가용한 임의 포트의 PHP 서버를 생성·정리합니다. DB 생성·삭제 권한이 있는 개발용 계정이 필요하며 `PHP_BIN`, `AUTH_TEST_PORT`로 실행 환경을 바꿀 수 있습니다. 지정 포트가 점유되어 있으면 DB 연결 전에 중단하고, 포트 양도 후에도 실행별 서버 식별값을 확인하여 다른 서버로 인증 요청을 보내지 않습니다. `.env` 파일이 없어도 프로세스의 임시 DB 설정이 적용되는지 별도로 검증합니다.

2026-10-18 검증: 회원 인증 41개, 기존 회원 스키마 31개, 환경 변수 우선순위 2개, 포트 충돌 보호 1개 통과. 기존 전체 수용 테스트는 별도 DB·업로드 폴더에서 수용 28개, 보안 2개, 운영 1개 통과. AC10 추가 입력 방식과 AC15 학교 LAN은 기존 수동 범위입니다.

실제 브라우저에서 홈 → 로그인 → 회원가입, 비밀번호 확인 불일치, 가입 후 로그인 이동, 잘못된 비밀번호 안내, 정상 로그인과 회원 이름, 새로고침 후 유지, 로그아웃 후 메뉴 복원을 확인했습니다. 360px 너비에서 상단 버튼·로그인 폼·회원가입 하단 이동 링크의 배치와 스크롤 접근을 확인하고 기본 화면 크기로 복원했습니다.

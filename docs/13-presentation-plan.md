## 14장 구성

| 슬라이드 | 내용 | 12장에서 바뀐 점 |
|---|---|---|
| 1 | 표지 | 그대로(콘셉트 이미지) |
| 2 | 프로젝트 소개 | 가입 없이 직접 만들거나 초대 코드로 입장, 학교 PC 1대 서버 + LAN 의 PC 4대 |
| 3 | 서비스 사용 흐름 | 작업실 만들기 → 초대 → 게스트 입장 → 보드 편집 → 자동 저장 |
| 4 | 화이트보드 화면 | 목업 대신 **실제 화면 캡처** |
| 5 | 핵심 기능과 우선순위 | PNG·JPG·WEBP 10MB, 외부 영상 임베드, 구현한 P1 항목 |
| 6 | 실시간 협업 | 미리보기는 저장 안 함, 잠금, 30초 만료·연결 종료 해제, 확정만 저장 |
| 7 | 시스템 구조 | Canvas API, 게스트 세션, 1회용 단기 티켓(60초) |
| 8 | 역할 분담 | A(본인 확정)·B·C·D 와 협업 방식 |
| 9~11 | 역할 상세 B·C·D | **실제 화면 캡처**, WBS 번호와 인계 대상 |
| 12 | 3주 계획과 시연 목표 | 주차별 완료 기준, P1 중단 기준 |
| 13 | 수용 테스트 결과 (신규) | 자동 23 · 브라우저 확인 3 · 실패 0 · **미실행 1(AC15)**, 보안 점검 1·운영 점검 1 과 4인 자동 리허설 13 통과 |
| 14 | 위험과 대응 (신규) | 학교 PC·네트워크 / 동시 편집·보안 / 3주 범위, 실패 시 축소 기준 |

모든 슬라이드에 발표자 노트가 있습니다. 표지와 2·6장의 그림은 기획 단계의 콘셉트 이미지이고, 4·9·10·11장의 화면만 실제 구현을 찍은 것입니다.

## 발표 전에 손볼 것

- **이름:** 8~11장의 A·B·C·D 를 실제 이름으로 바꿉니다. 팀원이 모두 확정되지 않아 역할 기호로 두었고, 누가 어떤 코드를 작성했는지는 자료에 적지 않았습니다.
- **13장:** 숫자는 2026-10-10 개발 PC 1대 기준입니다. 학교 PC 리허설을 마치면 AC15 행, "미실행 1" 카드, 발표자 노트를 결과에 맞게 고칩니다.
- **화면이 바뀌었을 때:** `apps/realtime` 에서 `npm run capture` 로 다시 찍은 뒤 PowerPoint 의 **그림 바꾸기**로 교체합니다.
- **글꼴:** 원본과 같이 NanumSquare 로 지정되어 있습니다. 설치되지 않은 PC 에서는 기본 한글 글꼴로 바뀌어 보입니다. 배치는 그 대체 글꼴 상태에서 확인했으므로, 나눔스퀘어가 설치된 PC 에서는 줄 길이가 조금 다를 수 있습니다. 발표 PC 에서 한 번 끝까지 넘겨 봅니다.

## 만든 방법과 확인

- 12장 파일을 복사해 내용을 고치고 13·14장을 같은 틀로 추가했습니다. 원본 두 파일은 바꾸지 않았습니다.
- 파일 구조 검사를 통과했고, PowerPoint 로 열어 14장을 모두 그림으로 내보내 글 넘침·겹침을 확인했습니다.
- 15단계에서는 파일을 다시 만들지 않고 13장의 왼쪽 아래 카드, 14장의 AC15 대응 문구, 두 장의 발표자 노트만 고쳤습니다. 다른 장은 건드리지 않았습니다.
- 16단계에서는 화면이 바뀌어(다시 실행 버튼, 글자 크기 목록, 큰 제목 글) 4·9·10·11장의 실제 화면 그림 4장을 새 캡처로 바꾸고 13장의 추가 확인 카드와 노트를 고쳤습니다. 그림 크기가 같아 배치는 그대로입니다.
- 17단계에서는 작업실에 업무 현황판이 생기고 업무 블럭에 마감 표시가 붙어 실제 화면 그림 4장을 다시 바꾸고, 3장의 작업실 설명과 13장의 숫자(수용 기준 26개, 자동 22, P1 11개, 리허설 13), 5·13장의 노트를 고쳤습니다.
- 18단계에서는 초대 코드 없이 작업실을 직접 만드는 기능이 생겨 2장의 입장 방법, 3장의 흐름 첫 단계, 13장의 숫자(수용 기준 27개, 자동 23, P1 12개)와 2·3·13장의 노트를 고치고 실제 화면 그림 4장을 다시 바꿨습니다.
- 장식용 곡선이 아래쪽 한 줄 문구와 살짝 겹치는 곳(7·9·10·11장)은 원본 12장의 디자인과 같습니다.

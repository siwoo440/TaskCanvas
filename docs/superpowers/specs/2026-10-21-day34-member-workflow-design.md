# 34일차 회원 작업 흐름 설계

---
## 목적과 승인 범위

사용자가 승인한 저장 뷰·회원 역할 관리·통합 검색·개인 홈·접근성 기본 흐름을 구현한다. 33일차의 기존 회원·게스트 연결과 업무 필터를 재사용한다.

---
## 동작 계약

- 저장 뷰: 로그인 회원별·작업실별 생성일/상태/담당자 필터, 이름 1~60자, 최대20개, 기본 뷰 한 개, version 충돌409, 타 회원 접근404. 현재 적용된 조건만 저장하며 필터 검증은 서버에서 수행한다.
- 멤버 관리: 로그인한 작업실 관리자가 기존 참여자의 역할 변경·내보내기. 같은 회원의 연결 게스트들을 함께 관리한다. 프로젝트 행 잠금과 최신 권한 재검사로 마지막 관리자 제거를 차단한다. 기존 초대 코드와 회원 참여 경로를 사용한다.
- 검색: 로그인 회원이 접근 가능한 작업실·보드·업무 제목/설명·메모 텍스트에서 1~80자 부분 문자열 검색. %와 _는 문자로 취급, 전체40개 상한, 서버에서 범위 검증, 결과 선택 시 최신 작업실 권한 재확인.
- 개인 홈: 본인 연결 게스트에게 배정된 미완료 업무20개, 3일 이내 마감 업무20개, 최근 보드10개, 보드 즐겨찾기 최대100개. 삭제·멤버십 해제 시 조회 제외. 방문 기록은 서버 권한 검사 후 저장한다.
- 키보드: Ctrl+K 검색, 한글 조합 중 Enter 미전송, 위/아래/Enter 선택, Esc 닫기와 원래 포커스 복원, dialog 기본 포커스 트랩, 색 외 상태 텍스트.
- 오래된 비동기 결과는 계정·작업실 변경 후 폐기한다. 비회원은 기존 기능을 계속 사용하며 회원 도구에는 로그인 안내를 제공한다.

---
## 구조와 검증

기존 project_members와 guest_user_links를 권한 원본으로 유지한다. dashboard_views·user_board_favorites·user_board_visits만 추가하며 신규 설치와 기존 DB 보정을 일치시킨다. PHP 서비스와 컨트롤러, 순수 JavaScript의 저장 뷰·개인 도구·역할 화면을 분리한다. 실제 API/DB로 소유권·타 작업실·버전·마지막 관리자·동시성·세션 만료를 검증하고 기존 수용 검사를 재실행한다.

---
## 완료 경계

34일차 기능 구현·검증과 저장소 문서 갱신까지 수행한다. 새 34일차 공유 브랜치 푸시는 이번 요청에 명시되지 않았으므로 완료 결과와 변경 파일을 전달한다. 역할 내보내기 동작은 개발한 UI/API로 제공하며 실제 사용자 멤버십을 임의 변경하지 않는다.

# 27일차 — 회원과 작업실 접근 권한 연결 설계

---
## 목적과 완료 조건

26일차 회원 인증을 기존 작업실·보드·실시간 편집에 연결한다. 기존 guest_id, 업무 담당자, 작성자, 업로드 참조를 보존한다. 회원은 초대로 작업실에 참여하고 자신이 가진 역할에 따라서만 조회·편집한다. 다른 회원의 게스트·작업실·티켓을 사용할 수 없어야 한다.

기존 게스트의 회원 연결은 회원 비밀번호 재확인과 현재 유효한 게스트 세션을 동시에 요구한다. 회원 연결을 선택하지 않은 비회원의 기존 작업 흐름도 유지한다.

---
## 선택한 방식과 대안

- 채택: 기존 guest_id와 멤버십을 유지하고 guest_user_links로 회원 소유를 확인한다. 회원 세션에 종속된 게스트 세션으로 기존 역할 검사 경로를 재사용한다.
- 대안: 모든 업무·멤버십·미디어·실시간 식별자를 user_id로 이전한다. 기존 데이터와 게스트 기능의 변경 범위가 커서 이번 범위에서 제외한다.
- 제외: 회원 쿠키의 존재만 확인하고 기존 게스트 쿠키를 그대로 신뢰하는 방식. 다른 회원으로 로그인하거나 로그아웃한 후 권한이 남는 문제가 있다.

---
## 식별자와 데이터 보정

| 변경 | 규칙 |
|---|---|
| guest_sessions.user_session_id | NULL 허용 BIGINT UNSIGNED. user_sessions.session_id 외래키, ON DELETE CASCADE. 비회원 세션은 NULL, 회원용 세션은 발급한 회원 세션 ID 저장 |
| realtime_tickets.guest_session_id | NULL 허용 BIGINT UNSIGNED. guest_sessions.session_id 외래키, ON DELETE CASCADE. 신규 티켓은 발급한 게스트 세션 ID 필수 저장 |
| guest_user_links | 25일차 구조 유지. guest_id당 회원 한 명, 회원당 여러 게스트 허용 |

신규 schema.sql과 기존 Schema.php 보정 정의를 동일하게 유지한다. 기존 세션 행은 보존하며 연결된 게스트의 결합 정보 없는 세션은 인증에서 거부한다. 기존 티켓 중 guest_session_id가 없는 티켓은 새 서버에서 거부한다. 배포 후 클라이언트는 티켓을 다시 발급받는다. 기존 업무·멤버십은 수정하지 않는다.

MemberAuth 내부 조회는 회원 세션 ID도 반환하되 공개 회원 응답에는 포함하지 않는다. 토큰 원문을 JSON·URL·저장소에 노출하지 않는다. 시연 초기화 순서에 새 외래키를 반영한다.

---
## HTTP 인증 규칙

1. 연결되지 않은 비회원 게스트는 기존 유효한 게스트 쿠키로 접근한다.
2. 회원 연결이 있는 게스트는 유효한 회원 쿠키, 같은 회원 소유의 연결, 해당 회원 세션에 종속된 게스트 세션이 모두 필요하다. 게스트 쿠키만 있으면 401이다.
3. 회원용으로 발급한 게스트 세션은 회원 세션 만료·폐기·교체 후 거부한다. 다른 회원 또는 같은 회원의 다른 브라우저 세션으로 대체할 수 없다.
4. 작업실 API는 기존 서버 역할 검사를 유지한다. 관리 작업은 admin, 편집은 editor 이상, 조회는 viewer 이상이다. 클라이언트가 보낸 역할·guest_id·user_id는 인증 근거로 사용하지 않는다.
5. 기존 미연결 게스트 쿠키를 가진 채 로그인한 경우 자동으로 소유를 이전하지 않는다. 화면에서 명시적으로 연결하거나 회원 작업실을 선택한다. 연결 없이 회원 작업실을 선택하면 미연결 게스트 데이터는 보존되지만 해당 브라우저의 활성 대상은 바뀐다.

## API 계약과 화면 흐름

기존 응답의 ok/error 형식, X-TaskCanvas 변경 헤더, no-store, HttpOnly 쿠키 정책을 유지한다.

| API | 입력과 처리 |
|---|---|
| GET /api/auth/workspaces | 회원 필수. 연결된 게스트들의 작업실 목록과 현재 게스트의 연결 가능 여부 반환. 다른 회원의 게스트 정보 노출 금지 |
| POST /api/auth/guest-link | password 필수. 현재 회원 비밀번호와 현재 게스트 세션의 소유 확인 후 연결. 본문의 식별자는 사용하지 않음 |
| POST /api/auth/workspaces/select | project_id 필수. 회원이 가진 멤버십 중 해당 작업실의 게스트를 선택하고 현재 회원 세션에 종속된 새 게스트 세션 발급 |
| POST /api/auth/workspaces/join | invite_code 필수. 유효한 초대와 사용 한도를 검사하여 회원의 게스트에 멤버십 추가. 기존 멤버십은 역할 상승·횟수 차감 없이 재사용 |
| POST /api/projects | 기존 경로 유지. 회원 상태에서는 본인 게스트로 작업실 생성 및 연결, 비회원은 기존 생성 흐름 유지 |
| GET /api/me | 기존 guest·projects 필드 유지. 유효한 회원용 게스트 세션에서는 회원이 연결한 게스트들의 작업실 목록 제공. 선택된 작업실과 guest_id가 일치하도록 전환 API 사용 |

새 회원에게 연결된 게스트가 없으면 서버가 회원 표시 이름으로 새로운 게스트를 생성한다. 이름이 같은 기존 게스트는 재사용하지 않는다. 회원별 최초 생성은 회원 행 잠금으로 직렬화한다. 로그인 직후 미연결 게스트가 있으면 연결 선택을 먼저 제공하고, 없으면 회원용 게스트 세션을 복원한다.

동일 회원의 여러 게스트가 같은 작업실에 참여한 경우 실제 보유한 역할 중 가장 높은 멤버십을 선택하고, 동률이면 guest_id가 작은 멤버십을 선택한다. 행·담당자를 병합하지 않는다. 응답의 역할과 활성 게스트는 이 선택 규칙으로 일치시킨다.

홈에 회원 작업실 목록·초대 코드 참여·현재 게스트 연결 버튼을 제공한다. 연결 버튼은 비밀번호 재확인 대화상자를 열며 취소·완료·화면 이탈 시 비밀번호를 비운다. 기존 작업실 전환 UI는 회원일 때 select API 성공 후 보드·업무·연결을 다시 불러온다. 회원 로그아웃 후 작업실 화면과 연결도 정리한다.

## 게스트 연결과 초대 보호

- guest-link는 요청 제한을 적용하고 회원 비밀번호 실패를 기록한다. 잘못된 비밀번호는 401, 게스트 없음은 401, 다른 회원 소유는 409로 거부한다.
- 회원·게스트 행을 일정한 순서로 잠그고 트랜잭션에서 소유를 재확인한다. 같은 회원 연결은 멱등적으로 성공하며 다른 회원 연결은 덮어쓰지 않는다.
- 최초 연결 시 해당 게스트의 기존 guest_sessions와 realtime_tickets를 모두 폐기하고 현재 회원 세션에 종속된 새 게스트 세션을 발급한다. 실패 시 전체 연결을 롤백한다.
- 이름 기반 GuestController::join은 이미 회원에 연결된 게스트를 재사용하지 않는다. 해당 이름이 연결된 게스트와 충돌하면 NAME_IN_USE로 거부하고 다른 이름 또는 회원 로그인을 안내한다.
- 게스트 재입장과 회원 연결이 동시에 실행되어도 이름 조회·게스트 행 잠금 후 연결 여부를 다시 확인한다.
- 회원 초대 참여는 표시 이름으로 타인의 멤버십을 찾지 않는다. 본인 멤버십 재사용 외 신규 참여는 유효한 초대 역할만 부여한다. max_uses=0은 신규 가입을 허용하지 않는다.
- 초대 만료·폐기·사용 한도 확인과 차감을 트랜잭션 안에서 처리한다. 회원의 동시 중복 가입은 멤버십·회원 잠금으로 중복 차감을 방지한다.
- 회원 연결 해제·다른 회원으로 이전·세션 분실 후 이름만으로 복구하는 기능은 제공하지 않는다.

## Socket.IO 세션 연계

보드·작업실 티켓 모두 발급 원본 게스트 세션에 결합한다. 티켓 소비 시 티켓 만료·일회성·대상 범위와 함께 게스트 세션, 회원 연결, 회원 세션, 최신 역할을 확인한다. 회원 쿠키를 Node 서버에 직접 전달하거나 자바스크립트로 읽지 않는다.

소켓에 서버가 확인한 게스트 세션 ID·회원 세션 ID·작업실을 저장한다. 참여 이후의 각 수신 이벤트에 공통 인증 가드를 적용하고, 기존 이벤트별 역할 검사는 유지한다. 만료·폐기된 세션 또는 제거된 멤버십은 이벤트 처리 전에 차단하고 연결을 해제한다. 인증 조회 오류도 접근 허용으로 처리하지 않는다.

유휴 연결도 1초 주기로 재검사해 서버 방에서 제거한다. 회원 연결·로그아웃·만료 후 기존 소켓은 다음 수신 이벤트 또는 다음 감시 주기에 끊긴다. 따라서 유휴 연결의 수신 차단에는 최대 감시 간격과 DB 처리 시간이 필요하다. 이미 처리 중인 요청까지 소급 취소하는 보장은 제공하지 않는다. 재연결은 새 티켓으로만 허용한다.

연결 해제 시 기존 presence·잠금 정리 경로를 사용한다. 프런트엔드는 인증 실패 시 자동 무한 재접속을 중단하고 로그인 또는 작업실 재선택 안내를 표시한다.

## 검증과 통합 기준

분리된 임시 DB·PHP·Node 포트에서 아래 항목을 검사한다. 실행별 서버 식별과 포트 충돌 보호를 유지한다.

- 신규 설치·기존 DB 보정 일치, 반복 실행, 기존 데이터 보존, 외래키·초기화 회귀.
- 회원 A/B 격리, 임의 ID로 소유 지정 불가, 비밀번호 재확인, 중복 연결, 동시 연결 충돌.
- 연결 전 세션·티켓·활성 소켓 재사용 거부, 같은 이름과 초대 코드로 연결된 게스트 탈취 불가.
- 회원 초대 신규 가입·재입장·한도·만료·폐기·역할 유지, 여러 작업실 전환 및 새로고침 복원.
- viewer 수정 거부, editor 관리 기능 거부, admin 허용, 다른 회원 작업실 API·티켓 접근 거부.
- 회원 세션 만료·로그아웃·재로그인 교체 후 HTTP·미사용 티켓·보드 소켓·작업실 소켓 차단. 다른 브라우저의 유효 세션은 유지.
- 인증 실패 소켓의 presence·잠금 정리, 잘못된 티켓과 보드·작업실 범위 혼용 거부.
- 기존 26일차 인증·25일차 스키마·게스트 수용 테스트 회귀. 학교 PC 4대 AC15는 별도 실환경 검증으로 계속 표시.
- 실제 브라우저에서 회원 작업실 생성 → 초대 참여 → 게스트 연결 → 전환 → 새로고침 → 로그아웃 흐름과 오류 안내 확인.

구현·검증 뒤 README·HTTP 명세·수용 테스트·WBS·27일차 결과 문서를 갱신한다. 이번 승인은 제품 구현 방향에 대한 것이며 실제 데이터의 일괄 연결이나 운영 DB 초기화를 허용하지 않는다.

# 32일차 — 데이터 품질 검사·보고서 상세 설계

2026-10-20. 최신 일정 E10과 사용자가 진행 요청한 32일차 개발 방향 기준. 현재 main 기준 커밋은 c3ea385다. 기존 31일차 저장 전 검증을 확장하며, 오류가 있으면 전체 저장 차단·원자적 저장·세션 및 작업실 권한 규칙을 유지한다.

---
## 1. 목적과 완료 조건

사용자는 파일 전체의 결측·자료형 오류·중복 위치를 확인하고 파일을 수정해 재검사한다. 보고서는 저장 당시 검사 조건과 예상 건수를 보존하고, 성공한 저장의 실제 건수와 대조한다. 완료 흐름은 업로드→매핑→전체 검사→요약/상세 확인→수정·재검사→확정 저장→새로고침 후 보고서 및 실제 결과 조회다.

원본·저장 데이터 자동 수정이나 오류 행 자동 제외는 하지 않는다. 숫자/날짜 변환·공백/키 비교는 기존 ImportValues 규칙을 재사용한다. 검사 규칙을 별도 화면 코드로 중복 구현하지 않는다.

---
## 2. 접근 방식

검사 결과를 DB에 보관하는 방식을 채택한다. 매 조회 원본 재검사 방식은 초안 만료·성공 후 원본 조각 삭제 때문에 과거 보고서를 재현할 수 없으며, 브라우저만 보관하는 방식은 재접속·권한 검사·DB 결과 대조를 보장하기 어렵다.

기존 ImportService의 전체 행 순회를 확장하고, 품질 집계·저장/조회는 별도 ImportQuality 서비스로 분리한다. 전체 행 값을 메모리에 복제하거나 거대한 오류 JSON 하나를 DB에 전송하지 않는다. 파서와 확정 저장 정책은 유지한다.

---
## 3. 검사와 수치 정의

| 항목 | 정의 |
| --- | --- |
| 수신 행 | 선택한 원본 배열/CSV의 데이터 행 전체, 헤더 제외 |
| 오류 행 | 저장 차단 오류가 하나 이상 있는 서로 다른 원본 행 |
| 정상 행 | 수신 행−오류 행. 중복 건너뛰기 행도 정상 행에 포함 |
| 오류 수 | 모든 저장 차단 오류의 합계. 한 행의 여러 오류는 각각 계산 |
| 결측 | 포함 컬럼의 원본 null·빈 문자열·공백만 있는 값. 잘못된 숫자를 null로 변환한 결과는 결측으로 세지 않음 |
| 컬럼 결측률 | 해당 컬럼 결측 수/수신 행 수×100, 소수 첫째 자리, 분모0이면0 |
| 파일 내부 중복 | 형식 검증을 통과한 키의 두 번째 이후 출현 행 |
| 기존 자료 중복 | 형식 검증을 통과한 키가 대상 데이터셋에 존재하는 행 |
| 저장 예상 | 기존 저장 엔진이 산출한 신규·갱신·건너뛰기 수 |

필수 결측·잘못된 숫자·잘못된 날짜·지원하지 않는 값/길이·행 구조 불일치는 오류다. 선택 컬럼 결측과 정책으로 처리하는 키 중복은 경고다. 파일 내부/기존 중복은 같은 행에서 겹칠 수 있으므로 두 건수를 더해 전체 중복 행 수로 표시하지 않는다. 중복 행 수는 합집합으로 별도 제공한다. 키 없음에서는 중복 판정을 하지 않으며 같아 보이는 행을 임의 병합하지 않는다.

제외 컬럼의 값 검사는 생략하되 원본 파일의 구조·크기 제한은 유지한다. 필드 오류 코드는 REQUIRED_MISSING·INVALID_NUMBER·INVALID_DATE·INVALID_CELL 등으로 구분하고 기존 메시지·위치 계약을 유지한다. 구조 오류는 필드 미지정 항목으로 분류한다.

## 4. 보관 구조와 수명

- import_quality_reports: run_id를 고유 키로 기존 import_runs와 결합. 보고서 형식 버전, 파일 메타데이터, 스키마/매핑·키·정책 스냅샷, 대상 ID/검사 version, 검사 시각, 요약/컬럼 집계, 저장 전 행 수, 예상 건수를 보관.
- import_quality_rows: run_id·source_row를 복합 고유 키로 문제 행의 압축된 항목 목록을 보관. 항목은 분류·심각도·원본 컬럼 ID 등이며 원문 셀·키 값·원본 파일·세션 토큰은 복제하지 않음. 표시 이름과 설명은 보고서의 스냅샷/고정 코드에서 복원.
- 검증 성공/실패와 관계없이 보고서와 검증 이력을 같은 트랜잭션에서 저장. 기록 실패 시 검증 성공 응답을 보내지 않음.
- 성공 저장에서 실제 신규/갱신/건너뛰기·저장 후 행 수·확정 version·시각을 같은 트랜잭션으로 기록. 실패/충돌은 확정 수치 없음으로 표시. 응답 유실 재시도는 같은 보고서에 결과 한 번만 반영.
- 초안 만료/원본 정리 후에도 보고서는 남음. 기존 이력에 보고서가 없으면 ‘상세 품질 보고서 없음’ 표시, 과거 수치를 추정해 생성하지 않음.
- 이력/작업실/데이터셋 삭제 시 기존 외래키 정책에 따라 연관 보고서를 정리. 신규 설치·기존 DB 보정·반복 실행에서 동일 정의, 기존 전체 행 보존.

보고서는 원본 제한10,000행·50열 안에서 문제 행만 기록한다. 행별 작은 조각으로 저장하고 단일 DB 패킷1MiB 환경을 유지한다. 상세 응답은 문제 행20개 단위로 제한하며, 전체 문제를 한 응답/JSON에 넣지 않는다.

## 5. API와 권한

기존 POST /api/projects/{id}/imports/validate 응답에 quality 요약과 run_id를 추가하고 기존 report·revision·정규화 미리보기 필드는 유지한다. editor 이상만 검사를 실행한다.

GET /api/projects/{id}/imports/runs/{runId}/quality: viewer 이상, 저장 당시 조건·요약·컬럼 집계·예상/실제 결과를 반환한다.

GET /api/projects/{id}/imports/runs/{runId}/quality/rows: viewer 이상, page·severity(error/warning)·type·column(source_id 또는 구조 전용 식별자) 필터를 적용한다. 한 행에 여러 문제가 있으면 조건에 맞는 항목만 반환하며, 페이지 총수는 필터에 맞는 서로 다른 행 수다. 기본은20행, 빈 결과1/1페이지, 큰 page는 마지막 페이지로 보정한다.

인증·작업실 멤버십을 먼저 검사한다. 조회 SQL마다 project_id와 run_id 범위를 제한하고 다른 작업실 보고서는404다. 잘못된/배열형/알 수 없는 조건은400, 응답은no-store. 셀 원문은 API에 포함하지 않는다. 초안 토큰을 URL에 넣지 않는다.

## 6. 화면과 저장 대조

전체 검증 결과에 수신·정상·오류 행·오류/경고·중복 요약과 컬럼별 결측 수/비율·자료형 오류 표를 추가한다. 상세 보고서에서 심각도·유형·컬럼 필터, 원본 행 번호·위치·설명과 페이지 이동을 제공한다. 기존 첫100건 오류 안내는 유지하며 전체 상세는 보고서에서 조회한다.

검사 직후와 가져오기 이력의 ‘품질 보고서’에서 같은 보고서를 연다. 파일명·검사 시각·스키마/정책·검사 대상 version을 표시한다. 검사 예상치와 실제 확정치를 별도 열로 제공하고 저장 전/후 행 수를 표시한다. 성공 시 수신=신규+갱신+건너뛰기, 저장 후=저장 전+신규, 예상=실제 여부를 확인한다. 저장 차단/충돌/실패는 예상치가 실제치인 것처럼 표시하지 않는다.

파일·매핑·정책 변경 시 현재 검사/저장 자격을 폐기한다. 과거 이력 보고서는 과거 조건임을 표시하며 현재 파일 검증 결과로 사용하지 않는다. 대상 version 변경 시 재검사를 요구한다. 계정/작업실 변경·화면 이탈·접근 상실과 응답 역전은 기존 세대 번호 방식으로 결과를 폐기한다. 다른 탭의 비활성 DOM 즉시 삭제는 기존처럼 미지원이며 탭 복귀·인증 이벤트로 정리한다. 모바일360px·내부 표 스크롤·연결 label·상태 안내·안전한 textContent 출력을 유지한다.

## 7. 검증과 통합

독립 기대값 표본으로 결측/형식오류/행수/경고/겹치는 중복 합집합, 정상 행·오류 수 구분, 제외 컬럼과 키 없음, 정상 값 정밀도 유지,100건 초과 오류 전체 페이지·복합 필터를 검증한다.

실제 분리 DB에서 보고서 신규/보정/반복/기존 행 보존, 초안 만료·성공 후 원본 삭제에도 보고서 유지, 다른 작업실/역할 접근, 보고서 없는 과거 이력, 같은 초안 동시 commit/재시도, 대상 version 충돌, 저장 중 SQL 오류 전체 롤백, 예상/확정/DB행수 일치를 검사한다. 원문/세션 비노출과1MiB 패킷에서 최대 입력의 행별 기록을 확인한다.

실제 브라우저에서 검사→필터/페이지→파일 수정 재검사→저장→새로고침→이력 보고서를 확인하고 고유 테스트 자료만 정리한다. 개발 DB는 먼저 백업하며 기존 스키마/행 보존을 대조한다. 기존31일차와 인증·통계·대시보드·수용 테스트를 회귀 실행한다. 직접 작성 코드는 Allman·줄별 짧은 한글 주석을 따른다.

사용자가 유지 요청한 main에서 직접 구현하고 독립 최종 코드 검토 후 32일차 단일 커밋으로 통합·푸시한다. 33일차 고급 필터·77일차 학교PC4대 현장 검증은 후속 범위다.

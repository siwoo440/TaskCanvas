# 33~40일차 압축 로드맵 설계

## 목표

32일차까지 구현한 회원 인증·통계 대시보드·파일 데이터 관리 기반을 유지하면서, 기존 33~78일차 계획을 수업 프로젝트의 필수 시연 결과 중심인 33~40일차로 압축한다.

## 확정 범위

- 33일차: 통합 필터·상태 이력·정확한 추이·CSV·차트 드릴다운
- 34일차: 저장 뷰·회원 역할·검색·개인 홈·접근성
- 35일차: 템플릿·활동 기록·알림
- 36일차: 보드 버전 복원·분할 작업공간
- 37일차: 오피스 파일 업로드·미리보기·원본 다운로드 MVP
- 38일차: 파일·저장·복구 안전장치
- 39일차: 공공데이터 API 한 종의 수집·저장·캐시
- 40일차: 전체 회귀·보안·학교 LAN·최종 제출 검증

## 범위 축소

브라우저 오피스 직접 편집, Drive OAuth, 외부 문서 임베드, 업무 의존 관계, 반복 업무, 조건 자동화, AI 요약은 필수 결과가 아니므로 후속 백로그로 이동한다. 오피스 범위는 원본을 변경하지 않는 업로드·미리보기·다운로드로 제한한다.

## 의존 관계

33일차의 필터와 이력 계약은 34일차 저장 뷰와 개인 홈의 기반이다. 36일차 버전 복원은 38일차 원자적 저장·복구 정책과 같은 원본 불변 원칙을 사용한다. 39일차 외부 데이터는 30~32일차 데이터셋·품질 검사 경로를 재사용한다. 40일차는 33~39일차의 완료 증거가 있는 기능만 검증 대상으로 삼는다.

## 안전 원칙

- 기존 1~32일차 데이터와 API 계약을 임의로 삭제하지 않는다.
- 모든 작업실 데이터는 서버 권한 검사를 거친다.
- 기록되지 않은 과거 이력을 추정하지 않는다.
- 외부 API 실패를 성공으로 표시하지 않는다.
- 파일 원본과 마지막 정상 저장본을 보존한다.
- 자동 브라우저 검증과 실제 학교 PC LAN 검증을 구분한다.

## 성공 기준

- 필수 수업 조건인 DB 회원 인증·DB 통계·자체 대시보드를 시연할 수 있다.
- CSV·JSON과 공공데이터 한 종을 DB에 저장하고 출처를 표시할 수 있다.
- 필터·차트·표·CSV의 수치가 동일한 원본 조건에서 일치한다.
- 권한·저장 실패·외부 API 장애 상황에서도 기존 정상 데이터를 잃지 않는다.
- 실제 학교 PC 4대 검증 결과와 제출 문서가 최신 구현 상태를 반영한다.

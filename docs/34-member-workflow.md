# 34일차 — 회원 작업 흐름

2026-10-21 구현. 회원별 조회 설정, 개인 홈, 통합 검색, 참여자 역할 관리, 키보드 기본 흐름을 추가했다. 기존 게스트 입장과 업무 통계 계약은 유지한다.

---
## 1. 사용 방법

- 로그인 후 개인 홈에서 내 미완료 업무·마감 임박·최근 보드·즐겨찾기를 확인한다. 업무는 같은 계정에 연결된 담당 게스트 기준이다.
- 보드 카드의 별 버튼으로 즐겨찾기를 등록·해제한다. 실제 보드 조회에 성공하면 최근 보드에 기록한다.
- 분석 대시보드의 ‘내 조회 설정 저장·불러오기’에서 이름과 기본 여부를 정하고 조회된 조건을 저장한다. 새 항목은 ‘새 조회 설정’, 수정은 기존 항목을 선택한다. 기본값은 다음 분석 진입 시 복원한다.
- 회원 관리자에게 ‘참여자 역할 관리’가 표시된다. 같은 계정의 모든 연결 이름에 역할 변경·내보내기를 함께 적용한다. 내보내기는 표시 이름을 정확히 입력해야 한다.
- Ctrl+K 또는 상단 빠른 검색으로 작업실·보드 제목, 업무 제목·설명, 메모 원문을 검색한다. 방향키로 결과 이동, Enter로 선택, Esc로 닫으며 호출 요소로 초점을 복원한다. 한글 조합 중 Enter는 실행하지 않는다.
- 검색 결과는 서버가 접근 권한을 다시 확인한 후 이동한다. 업무는 열람자에게 읽기 전용으로 표시한다.

---
## 2. 데이터와 제한

| 자료 | 소유·범위 | 한도 |
|---|---|---|
| dashboard_views | 회원+작업실, 이름 중복 금지 | 20개, 이름 1~60자, 기본값 1개 |
| user_board_favorites | 회원+보드 | 100개 |
| user_board_visits | 회원+보드 | 개인 홈 최근 10개 |
| 내 업무 | 현재 참여 작업실의 본인 미완료 업무 | 최근 20건 |
| 마감 임박 | 서울 오늘부터 3일 뒤까지의 본인 미완료 업무 | 20건 |
| 검색 | 현재 참여 작업실만 | 검색어 1~80자, 유형별 10개·총 40개 |

저장 조건은 생성 시작일·종료일·상태·담당자만 포함한다. 분석 조회 성공 조건만 저장하며 최대 366일 검증을 재사용한다. 데이터셋은 업무 원본과 합치지 않고 기존 별도 화면을 유지한다. `%`와 `_`는 검색 와일드카드가 아닌 입력한 문자로 검색한다.

회원별 설정은 다른 회원에게 노출하지 않는다. 삭제된 보드의 개인 기록은 FK로 제거하며, 내보내진 작업실의 자료는 개인 홈과 검색에서 제외한다. 재참여 전까지 저장 설정에도 접근할 수 없다. 새 즐겨찾기 등록 시 이미 접근이 해제된 본인 즐겨찾기를 정리해 숨은 기록이 한도를 막지 않도록 한다. 정리된 즐겨찾기는 재가입 시 자동 복원하지 않는다.

## 3. API

모든 경로에 회원 쿠키가 필요하다. 변경 요청에는 `X-TaskCanvas: 1`을 요구한다. 기존 게스트 권한만으로는 사용할 수 없다.

| 메서드·경로 | 요청·응답 |
|---|---|
| GET /api/auth/home | tasks·due_soon·favorites·recent |
| GET /api/auth/search?q=검색어 | results(kind·id·project_id·board_id·title), limit=40 |
| POST /api/auth/boards/{id}/favorite | active: true/false, 멱등 등록·해제 |
| POST /api/auth/boards/{id}/visit | 빈 객체, 실제 권한 확인 후 방문 시각 갱신 |
| GET /api/projects/{id}/analytics/views | views 목록, 본인 설정만 |
| POST /api/projects/{id}/analytics/views | name·filters·is_default, 수정 시 view_id·version |
| POST /api/projects/{id}/analytics/views/{viewId}/delete | version, 본인 설정만 |
| GET /api/projects/{id}/members/manage | members, 회원 관리자만 |
| POST /api/projects/{id}/members/role | target_guest_id·role(admin/editor/viewer) |
| POST /api/projects/{id}/members/remove | target_guest_id·confirm_name |

소유하지 않은 설정은 404, 작업실 접근 불가는 403, 이름 중복·버전 충돌·한도·마지막 관리자 변경은 409다. 역할 변경은 프로젝트 행 잠금으로 직렬화하고 최신 회원 세션을 재검사한다. 두 관리자가 동시에 자신을 강등해도 관리자 한 명을 보존한다. 같은 회원의 모든 별칭을 함께 처리해 최고 역할 복원 우회를 막는다.

Socket.IO는 매 패킷과 유휴 감시에서 현재 역할을 확인한다. 역할 변경 시 기존 역할 연결은 `SESSION_EXPIRED` 후 종료하고 새 역할로 작업실을 다시 선택한다. 대상의 아직 사용하지 않은 실시간 티켓도 회수한다.

## 4. 설치·검증

기존 개발 DB는 `C:/xampp/php/php.exe apps/php-api/bin/migrate.php`로 새 표 3개만 보정한다. 신규 설치와 보정 구조 일치·반복 보정 안전성을 검사했다. 기존 자료 삭제나 원격 DB 변경은 없다.

| 검사 | 결과 |
|---|---|
| PHP member-workflow-schema.php | 10개 통과, 회원 표 없는 구형 DB 보정 포함 |
| Node test-member-tools.js | 실제 분리 DB·PHP API 42개 통과 |
| test-saved-views.js | 기본 복원·안전 출력·성공 조건·버전·늦은 응답 폐기 통과 |
| test-member-tools-client.js | 개인 홈·검색·이동·초점·로그아웃 폐기·별칭 묶음·역할 요청 통과 |
| test-role-guard.js | 역할 변경 패킷 차단·ACK·연결 해제 통과 |
| test-member-navigation.js | 최초 신원·선택·재조회·하위 업무의 계정 변경 응답 폐기 통과 |
| 기존 회원 인증·접근 | 41개·59개 통과 |
| 기존 통계·대시보드 | 40개·50개 통과 |
| 기존 대시보드 클라이언트 | 차트·역전 응답·인증·초안·실패·폐기 통과 |
| 전체 분리 수용 | 자동 28개·보안 2개·운영 1개 통과, 실패 0개 |

실제 브라우저에서 가상 회원의 개인 업무·마감·즐겨찾기·방문 기록, 기본 조회 저장, Ctrl+K 한글 메모 검색, 방향키·Enter 원본 보드 이동, Esc·호출 초점 복원을 확인했다. 학교 PC 4대 LAN(AC15)과 기존 AC10의 파일 추가 입력 방식은 이 일차에서 실행하지 않았다. 스크린리더 전반 및 브라우저 전체 호환성을 완료한 것으로 표시하지 않는다.

최종 읽기 전용 검토 후 구형 DB의 FK 생성 순서, 계정 변경 뒤 지연 작업실 응답, 저장 보기 입력 잔존, 접근 불가 즐겨찾기의 숨은 한도, 회원 묶음의 최고 역할 표시를 각각 실패로 재현하고 수정했다. 최초 구현 인계 뒤 사용자의 후속 요청에 따라 기존 일차별 제목·본문 형식의 34일차 커밋으로 정리한다.

## 5. 다음 35일차

템플릿·전체 활동 기록·협업 알림을 묶어 개발한다. 먼저 실제 행위자·변경 전후·시각을 기록하는 활동 계약을 정하고, 템플릿 복제는 접근 권한·멤버십·초대 코드·회원 개인 설정을 복제하지 않도록 분리한다. 알림은 담당자 배정·마감·중요 변경의 수신자와 읽음 상태를 보존하며 중복·본인 알림을 방지한다. 34일차 역할 변경 이후에도 타 작업실 기록과 알림이 노출되지 않는지 검증한다.

# 33일차 — 분석 이력·CSV·드릴다운 완성

---

## 1. 구현 결과

- Socket.IO `task:update`에서 실제 상태가 바뀐 경우에만 상태 이력을 업무 변경과 같은 트랜잭션에 저장한다.
- 작업실별 `request_id` 고유 제약과 `INSERT IGNORE`로 같은 요청의 재시도 이력 중복을 막는다.
- 새 변경에서 이미 사용한 요청 키가 충돌하면 업무 변경과 이력을 함께 취소한다. 이전 버전 재전송은 `VERSION_CONFLICT`로 거부하며 새 이력을 만들지 않는다.
- 대시보드는 기록된 상태 변경만 `status_trend`로 집계하며 기존 업무의 과거 완료 시각을 추정하지 않는다.
- 상태·담당자 차트를 선택하면 같은 기간과 조건으로 상세 업무를 다시 조회한다.
- 상세 업무는 연결된 원본 보드로 이동하며 보드가 없거나 사라진 경우 안내한다.
- CSV는 대시보드와 같은 기간·상태·담당자 조건의 전체 업무를 UTF-8 BOM으로 내려준다.
- CSV는 500행씩 같은 읽기 스냅샷에서 조회하고 2MiB 초과 자료는 임시 디스크로 보관한다. 수식 기호를 이스케이프하고 조회 중·실패 후에는 이전 다운로드 링크를 비활성화한다.

## 2. 데이터와 API

`task_status_history`는 작업실·업무·변경 전후 상태·게스트·연결 회원·요청 키·실제 변경 시각을 보존한다. 업무 또는 작업실 삭제 시 해당 이력도 외래키로 정리된다.

- `GET /api/projects/{id}/analytics/dashboard`: `status_trend`와 행별 `board_id` 추가
- `GET /api/projects/{id}/analytics/export`: 같은 필터의 전체 업무 CSV
- Socket.IO `task:update`: 상태 변경 시 멱등 이력 기록

데이터셋과 업무 사이에는 현재 관계 키가 없다. 따라서 가져온 데이터셋을 업무 KPI 필터로 오인하지 않고 데이터 관리 화면에 분리했다.

기간은 **업무 생성일** 기준이다. 추이는 그 조건에 해당하는 현재 업무 중, 같은 기간에 실제 기록된 도착 상태별 전환 횟수다. 같은 업무가 다시 완료되면 전환 횟수는 늘어날 수 있어 현재 완료 업무 수와 다를 수 있다. 담당자·상태는 현재 값 기준이며 업무 삭제 시 이력도 삭제된다. 전체 활동 감사 로그는 35일차 범위다. 기록 전 기간의 0은 기록된 전환이 없다는 뜻이다. `기타` 상태 조각은 표시만 제공하며 드릴다운하지 않는다.

기존 설치는 서버 실행 전에 `C:\xampp\php\php.exe apps/php-api/bin/migrate.php`를 실행한다. 시작 배치 파일은 이 보정을 자동 실행하며 기존 데이터 행은 보존한다.

---

## 3. 화면 사용법

1. 작업실에서 `분석 대시보드`를 연다.
2. 기간·상태·담당자를 선택하고 `조회`를 누른다.
3. 상태 도넛 또는 담당자 막대를 선택해 상세 조건을 적용한다.
4. 업무 표의 `보드 열기`로 원본 보드에 이동한다.
5. `CSV 내보내기`로 현재 서버 적용 조건의 전체 행을 저장한다.

## 4. 검증 결과

- 격리 MariaDB·PHP 대시보드 통합 검사 50개 통과
- 차트·클라이언트 상태 검사 통과
- 상태 이력 스키마 검사 11개, 분석 이력 7개, CSV 실제 바이트·파싱·1,003행 분할 검사 8개 통과
- 실제 Socket.IO 업무 핸들러와 고유 DB를 사용하는 재시도·키 충돌·순환 재사용·동시 수정·롤백·UTC 세션의 서울 자정 검사 통과
- PHP 구문과 Node.js 구문 검사 통과
- 전체 수용 자동 28개·보안 2개·운영 1개 통과
- 실제 8080 브라우저에서 빈 결과, 업무 생성·완료 전환 후 1건·완료율 100%, 완료 차트 선택과 `status=done` CSV 링크, 연결된 보드 없음 안내 확인
- 원본 보드 ID·작업실 격리는 API 검사, 이동 콜백·삭제 안내는 클라이언트 검사로 확인
- 학교 PC 4대 LAN 검증은 40일차 현장 범위

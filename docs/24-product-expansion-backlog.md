# TaskCanvas 추가 기능 백로그 — E01~E14

> 2026-10-18 신규 개발 계획. 모든 E01~E14는 아직 미구현이며, 기존 1~24일차 구현·검증 기록과 25~35일차 필수 과제 상태는 그대로 유지한다. 아래 '일차'는 달력 날짜나 소요 기간이 아닌 개발 순번이다.

---

## 1. 개발 범위 및 기존 기능과의 차이

- **필수 우선:** R01~R05 회원 DB 인증·SQL 분석·차트·필터와 R10 통합 테스트, AC15 실제 학교 LAN 4대 검증을 먼저 완성한다.
- **외부 데이터 우선:** R06~R09의 CSV/JSON/API 데이터 수집·출처·업무 상태 이력의 기본 구현을 먼저 완성한다.
- **추가 기능:** E01~E14는 별도 제품 확장이다. 기존 마감 색깔(E03과 차이), 단기 실행 취소(E04와 차이), 보드 그림 연결선(E07과 차이), 임시 필터(E09와 차이), 기본 업로드 유효성 검사(E10과 차이), 기존 게스트 역할(E11과 차이), 업무 상태 이력(E13과 차이)을 서로 혼동하지 않는다.
- **우선순위:** P1+는 과제 필수 범위 완료 후 권장, P2는 후속 고난도 선택 기능.

## 3. 기능별 사용 흐름·DB 설계·완료 기준

### E01. 차트 드릴다운·원본 이동
- 사용 흐름: 그래프의 진행 중 또는 담당자 영역 클릭 → 동일 필터의 업무 목록 → 업무 상세 → 실제 보드 객체에 포커스. 원본 블럭이 없으면 상세만 제공.
- 구조: 기존 tasks·board_objects 관계와 집계 API/목록 API의 공통 서버 필터 사용.
- 완료 기준: 차트 건수와 목록 결과 수 일치, 다른 작업실 접근 차단, 블럭 삭제 시 안전 처리.

### E02. 통합 검색·빠른 이동
- 사용 흐름: Ctrl+K로 작업실·보드·업무·메모 검색 후 엔터로 이동.
- 구조: 검색 API, DB 인덱스, 프로젝트별 권한 검증, 결과 건수 상한.
- 완료 기준: 무권한 대상 0건, 한글 입력·ESC·키보드 탐색 정상.

### E03. 알림함
- 사용 흐름: 배정·마감 임박·중요 변경 알림 표시, 읽음/모두 읽음과 원본 이동.
- 구조: notifications(수신자·대상·유형·읽음 시간·중복키), 조회·읽음 API.
- 완료 기준: 중복 발송 방지, 수신자만 열람, 재로그인 후 상태 유지.

### E04. 화이트보드 버전·복원
- 사용 흐름: 확정 저장본 목록과 미리보기 확인 후 권한 있는 사용자가 과거 버전 복원.
- 구조: board_revisions(보드·버전·스냅샷·작성자·시간), 충돌 검사 및 복원 API.
- 완료 기준: 복원 전 현재 상태 백업, 동시 편집 충돌 방지, 전 참여자 상태 일치. 실행 취소와 별개.

### E05. 프로젝트·보드 템플릿
- 사용 흐름: 빈 보드 또는 팀 과제·게임 개발·개인 일정 템플릿으로 시작.
- 구조: 템플릿 정의/선택, 생성 API와 안전한 업무·보드 복제.
- 완료 기준: 복사본에는 새 ID만 사용하고 원본 소유자·멤버십/권한 정보가 복사되지 않음.

### E06. 개인화 홈
- 사용 흐름: 내 업무·임박한 마감·최근 보드·즐겨찾기 표시.
- 구조: user_favorites와 최근 접근 정보, 로그인 회원별 홈 조회.
- 완료 기준: 타 회원/타 작업실 정보 차단, 삭제된 항목 자동 숨김.

### E07. 업무 선후행 의존성
- 사용 흐름: A 완료 전 B를 차단, 선행 업무 바로가기 제공.
- 구조: task_dependencies 별도 DB 관계. 보드 연결선과 구별되는 실제 업무 규칙.
- 완료 기준: 순환 관계 및 다른 프로젝트 업무 연결 거부, 변경·삭제 시 상태 정합성.

### E08. 반복 업무
- 사용 흐름: 매일/매주/매월 자동 생성 규칙과 다음 생성일·중지 기능.
- 구조: recurrence_rules와 실행 로그, 서버 스케줄러/멱등성 키.
- 완료 기준: 같은 주기 중복 생성 차단, 시간대·말일·중지 처리.

### E09. 대시보드 저장 뷰
- 사용 흐름: 상태·기간·담당·데이터셋 필터/차트 구성을 개인 뷰로 저장·열기.
- 구조: dashboard_views의 소유 회원·프로젝트·필터 JSON·기본 여부, CRUD API.
- 완료 기준: 재로그인 후 복원, 타 사용자 뷰 접근 거부, 삭제된 데이터셋 처리.

### E10. 데이터 품질 검사
- 사용 흐름: CSV/JSON/공공데이터 불러오기에서 누락·중복·잘못된 수치/날짜 검사 결과 제공.
- 구조: import_runs의 검사 집계와 오류 행·제외 사유 보고.
- 완료 기준: 검증·저장·제외 건수 일치, 오류 데이터 통계 반영 금지.

### E11. 회원 기반 멤버 관리
- 사용 흐름: 정식 회원 초대·역할 변경·내보내기·마지막 관리자 보호.
- 구조: 회원 멤버십·초대 흐름, 서버 세션 및 Socket.IO 티켓 권한 즉시 재확인.
- 완료 기준: 마지막 관리자 삭제 방지, 권한 변경 즉시 적용, 기존 게스트 기능 회귀 없음.

### E12. 접근성·단축키
- 사용 흐름: 키보드 이동·포커스·도움말·명도 대비·상태 텍스트 제공.
- 구조: UI 컴포넌트와 접근성 테스트 보강.
- 완료 기준: 로그인→업무→통계 상세를 키보드로 사용 가능, 색깔만으로 상태 구분 금지.

### E13. 전체 업무 활동 이력
- 사용 흐름: 누가 언제 업무 생성·상태·담당자·마감·삭제를 수행했는지 타임라인 조회.
- 구조: R09 상태 이력 확대 또는 task_activity_events(actor·이벤트·전후값·시간).
- 완료 기준: 실제 DB 이벤트와 로그 일치, 기록 수정 권한 차단, 과거 미기록 활동 날조 금지.

### E14. 조건 기반 자동화
- 사용 흐름: 체크리스트 완료→업무 완료, 마감 전 알림, 업무 완료→다음 담당자 안내.
- 구조: automation_rules와 automation_runs, 서버 트리거/실패 이력.
- 완료 기준: 중복 실행·순환·권한 상승 방지, 비활성화·재시도·실패 기록 동작.

## 6. 공통 제약 및 공개 기준

- 모든 검색·활동 기록·알림·대시보드 목록 API는 로그인 및 프로젝트 권한을 서버에서 검증한다.
- 데이터셋 출처·단위·수집 시각·예시 여부를 보존한다. 실제/예시 데이터를 섞어 집계하지 않는다.
- 복원·템플릿 복제·반복 실행·자동화에는 필요한 DB 트랜잭션과 멱등성/버전 충돌 규칙을 둔다.
- 비밀번호·토큰·서비스키를 활동 기록에 기록하지 않고 보존/삭제 정책을 설계한다.
- 0건·대량·네트워크 장애·권한 상실·삭제된 대상·한글·키보드 접근을 검증한다.
- **게이트 A:** R01~R05, R10, AC15 완료. **게이트 B:** R06~R09 완료 후 E01/E10/E09. **게이트 C:** E11/E02/E06/E05/E13/E03/E07/E08/E12. **게이트 D:** 복원·자동화(E04/E14) 별도 안전 검증.
- 상태는 실제 코드·테스트 결과가 있을 때만 미구현/계획 → 개발 중 → 테스트 통과 → 완료로 변경한다.

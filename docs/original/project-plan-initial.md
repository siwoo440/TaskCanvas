# **실시간 협업 캔버스 기반 프로젝트 관리 웹사이트**

프로젝트 기획서 | TaskCanvas (가칭)

웹서버 수업 팀 프로젝트 · 기획 초안 · 2026년 10월

팀원을 초대해 프로젝트를 관리하고, 하나의 온라인 도화지에서 작업 블럭·연결선·메모·자유 드로잉을 실시간으로 함께 편집하는 협업 플랫폼을 설계한다.

# **1\. 프로젝트 개요**

# **1.1 프로젝트 정의**

프로젝트명(가칭): TaskCanvas / CollabBoard

한 줄 소개: 프로젝트 업무 관리와 실시간 화이트보드를 하나의 웹사이트에서 제공하는 시각적 협업 서비스.

구현 환경: HTML, CSS, JavaScript, PHP, XAMPP(Apache), MySQL을 기본으로 하며, 실시간 공동 편집을 목표로 할 때 Node.js와 Socket.IO를 별도 연동한다.

# **1.2 기획 배경과 목표**

• 일반 업무 관리 도구의 카드·목록 중심 UI와 아이디어 구상용 화이트보드가 분리되어 발생하는 작업 전환을 줄인다.

• 팀원들이 같은 보드에서 업무 흐름, 우선순위, 관계도를 시각적으로 구성하도록 한다.

• 웹서버 수업의 핵심 요소인 인증, 세션, CRUD, 관계형 DB, 권한 검사, 비동기 통신을 실제 서비스 형태로 구현한다.

# **1.3 주요 사용자 및 활용 사례**

• 대학 팀 프로젝트: 역할 분담, 일정 계획, 회의 아이디어 정리, 작업 진행 상황 공유.

• 게임 및 소프트웨어 개발팀: 기능 목록, 화면 흐름, 버그·이슈, 개발 의존 관계 시각화.

• 스터디·동아리: 공동 기획, 행사 준비, 자료 링크, 작업 완료 현황 확인.

# **2\. 서비스 구성 및 사용 흐름**

# **2.1 사이트 주요 메뉴**

| 메뉴 | 주요 기능 |
| :---: | :---: |
| Dashboard | 활성 프로젝트·대기 작업·완료 작업·마감일 및 칸반 요약 |
| Projects | 프로젝트 목록·생성·설정·상세 조회 |
| Team | 구성원·초대 상태·역할·권한 관리 |
| Calendar | 업무 마감일·회의 일정 확인 |
| My Tasks | 나에게 할당된 작업 조회·상태 관리 |
| Files/Docs | 프로젝트 참고자료·파일 관리(확장 기능) |
| Board | 블럭·연결선·메모·드로잉을 함께 편집하는 협업 화이트보드 |

# **2.2 기본 사용 흐름**

① 회원가입·로그인 → ② 프로젝트 생성 → ③ 초대 링크로 팀원 참여 → ④ 업무 카드 작성·담당자 지정 → ⑤ 보드 개설 → ⑥ 블럭 연결 및 공동 드로잉 → ⑦ 완료 상태·일정 확인 → ⑧ 보드 및 작업 내역 저장.

# **3\. 핵심 기능 요구사항**

# **3.1 회원·팀·프로젝트 관리**

• 회원가입, 로그인, 로그아웃, 프로필 수정 및 로그인 세션 유지.

• 프로젝트 생성·수정·보관, 프로젝트 목록 조회, 이름·설명 설정.

• 프로젝트 전용 초대 링크 또는 초대 코드 발급·만료·취소.

• 사용자별 권한: 소유자(설정·삭제), 관리자(팀·업무 관리), 편집자(작업·보드 편집), 열람자(읽기 전용).

• 프로젝트 멤버십을 서버에서 검사하여 외부 사용자의 비인가 접근 차단.

# **3.2 업무 관리와 대시보드**

• 작업(Task) 제목, 설명, 담당자, 우선순위, 마감일, 상태 등록 및 수정.

• 업무 상태: To Do / In Progress / Completed.

칸반 목록에서 상태 이동.

• 나의 업무 필터, 상태·우선순위·담당자별 검색과 정렬.

• 프로젝트별 진행률, 완료 수, 미완료 수, 임박한 마감일 요약 표시.

• 달력에서 업무 마감일 확인, 업무 상세로 이동.

# **3.3 화이트보드: 블럭과 객체**

| 객체/기능 | 세부 요구사항 |
| :---: | :---: |
| 블럭 종류 | 작업 카드, 아이디어, 메모, 참고 링크, 텍스트, 도형 |
| 객체 편집 | 생성·선택·이동·크기 조절·복제·삭제·색상 변경·순서 조정 |
| 업무 연동 | 담당자·진행 상태·우선순위·마감일 표시 및 Task 데이터 연결 |
| 캔버스 이동 | 확대·축소(Zoom), 화면 이동(Pan), 배경 격자 |
| 저장 데이터 | 고유 ID, 좌표, 크기, 내용, 스타일, 작성자, 수정 시각 |

# **3.4 화이트보드: 연결선·자유 필기**

| 도구 | 세부 요구사항 |
| :---: | :---: |
| 연결선 | 블럭 간 직선·화살표 연결, 연결선 삭제, 블럭 이동 시 따라가기 |
| 연결선 라벨 | ‘선행 작업’, ‘관련 자료’, ‘의존 관계’ 등의 관계 설명 |
| 자유 필기 | 펜, 색상·굵기, 지우개, 선택형 형광펜, 기본 도형 |
| 메모·링크 | 텍스트 박스, 스티키 노트, URL 입력 및 외부 링크 열기 |
| 필기 복원 | 펜 좌표 경로(점 목록), 색상, 굵기를 저장해 재접속 시 복원 |

# **3.5 실시간 공동 편집**

• 같은 보드에 접속한 모든 사용자에게 객체 생성·수정·이동·삭제와 펜 획을 즉시 전파.

• 현재 접속자 수, 사용자별 이름·색상을 표시.

사용자 커서 공유는 추가 기능으로 분리.

• 서버를 통해 권한을 검증한 작업 이벤트만 브로드캐스트하고 DB에 최종 상태 기록.

• 재접속 시 DB의 최신 보드 상태를 다시 불러와 화면 복원.

• 최소 버전은 동일 객체에 대한 충돌을 ‘마지막 확정 저장 우선’으로 처리하고 복잡한 공동 텍스트 병합은 제외.

# **4\. 화면 구성 설계**

# **4.1 Dashboard**

첨부된 참고 이미지와 같은 카드형 레이아웃을 기준으로 한다.

좌측 사이드바에 메뉴를 배치하고 상단에는 검색·알림·프로필을 표시한다.

• 상단 KPI 카드: Active Projects / Pending Tasks / Completed Tasks / Upcoming Deadlines.

• 중앙 작업 보드: To Do / In Progress / Completed의 3열 칸반 카드.

• 오른쪽 영역: 소형 일정 달력과 곧 있을 약속·회의.

• 카드 클릭 시 해당 업무 상세 또는 프로젝트 보드로 연결.

# **4.2 프로젝트 상세**

상단에 프로젝트명, 설명, 멤버, 초대 버튼을 배치한다.

내부 탭은 개요 / Tasks / Board / Calendar / Members로 구성한다.

# **5\. 기술 스택 및 시스템 구조**

# **5.1 수업 기술 중심 기본 구성**

| 구성 | 기술 및 담당 기능 |
| :---: | :---: |
| 프론트엔드 | HTML·CSS·JavaScript: 화면 표시, 사용자 입력, API 호출, 도화지 편집 |
| 웹서버 | Apache(XAMPP) \+ PHP: 로그인 세션, 프로젝트·업무 API, 권한 확인 |
| 데이터베이스 | MySQL/MariaDB: 사용자, 프로젝트, 멤버, 작업, 보드 객체 및 링크 |
| 보드 렌더링 | HTML+SVG 연결선 또는 Konva.js/Fabric.js로 객체·드로잉 관리 |

# **5.2 실시간 구현 방식 비교**

| 방식 | 동작 및 장점 | 제약사항 |
| :---: | :---: | :---: |
| A. PHP \+ AJAX 폴링 | 1\~3초 주기로 변경 내용을 조회; 수업 기술만으로 구축이 상대적으로 쉬움 | 완전한 즉시 반영이 아니며 요청량 증가 |
| B. PHP \+ Node.js \+ Socket.IO | 양방향 이벤트로 변경을 즉시 공유; 동시 편집 시연에 적합 | 별도 프로세스 운영·인증 연계와 이벤트 처리 필요 |

추천: 기본 기능을 PHP \+ MySQL로 먼저 완성하고, 보드 편집이 안정화되면 Socket.IO를 추가한다.

Node.js 서버 허용 여부는 수업 조건에 따라 확인한다.

# **5.3 이벤트와 저장 처리 예시**

사용자 A가 블럭 이동 → 브라우저가 object:moved 이벤트 전송 → 실시간 서버가 보드 참여 권한 확인 및 변경 저장 → 같은 보드에 입장한 사용자 B·C에게 새 좌표 전송 → 각 화면에서 해당 블럭과 연결선 다시 그리기.

드래그 중에는 위치 이벤트를 일정 주기로 제한하고, 마우스를 놓았을 때 최종 좌표를 반드시 저장한다.

보드 접속 시 초기 객체 목록을 API로 받은 후 실시간 이벤트를 구독한다.

# **6\. 데이터베이스 설계 초안**

# **6.1 기본 테이블**

| 테이블명 | 주요 필드 및 제약사항 |
| :---: | :---: |
| users | user\_id(PK), name, email(UNIQUE), password\_hash, profile\_image, created\_at |
| projects | project\_id(PK), owner\_id(FK→users), title, description, created\_at |
| project\_members | project\_id(FK), user\_id(FK), role, joined\_at; (project\_id, user\_id) 복합 UNIQUE |
| project\_invitations | invitation\_id(PK), project\_id(FK), token\_hash, role, expires\_at, used\_at |
| tasks | task\_id(PK), project\_id(FK), assignee\_id(FK→users, NULL 허용), title, description, status, priority, due\_date, created\_at, updated\_at |
| boards | board\_id(PK), project\_id(FK), title, created\_at, updated\_at |

# **6.2 보드 테이블**

| 테이블명 | 주요 필드 및 용도 |
| :---: | :---: |
| board\_objects | object\_id(PK), board\_id(FK), task\_id(FK, NULL 허용), type, x, y, width, height, content\_json, style\_json, created\_by, updated\_at |
| board\_links | link\_id(PK), board\_id(FK), from\_object\_id(FK), to\_object\_id(FK), label, style\_json |
| board\_events (선택) | event\_id(PK), board\_id(FK), user\_id(FK), action\_type, payload\_json, created\_at; 변경 이력 및 복구 |
| attachments (확장) | attachment\_id(PK), project\_id(FK), task\_id(FK, NULL 허용), file\_path, uploaded\_by, created\_at |

# **6.3 데이터 관계와 설계 원칙**

users ↔ project\_members ↔ projects(다대다), projects → tasks(일대다), projects → boards(일대다), boards → board\_objects / board\_links(일대다).

보드 연결선의 출발·도착 객체가 같은 보드에 속하는지 서버 측에서 검증한다.

DB 테이블명과 필드는 초기 제안이며 수업에서 사용할 MySQL/MariaDB 버전과 구현 범위에 맞게 수정한다.

# **7\. 보안 및 안정성 필수 조건**

• 비밀번호는 PHP password\_hash / password\_verify로 해시 처리하며 평문 저장 금지.

• DB 접근은 PDO 준비된 문장(Prepared Statements)을 사용해 SQL 인젝션 위험을 낮춘다.

• 출력 텍스트 이스케이프, 저장 데이터 검증, 링크 URL 허용 프로토콜 검사로 XSS 방지.

• 세션 쿠키 보안 설정(HttpOnly, SameSite, 운영 환경 HTTPS에서 Secure)과 로그인 세션 재발급.

• 프로젝트 ID, 보드 ID, 작업 ID를 입력받는 모든 API에서 해당 사용자 멤버십과 권한 확인.

• 상태 변경 요청에 CSRF 방어 적용.

Socket.IO 연결 시 인증 및 보드 입장 권한 검사.

• 초대 토큰 만료·회수, 파일 업로드 형식·크기 제한, 예외 메시지에서 내부 정보 노출 금지.

| 1주 차 | 요구사항 확정, 와이어프레임, DB ERD, Git 저장소 및 업무 분장 |
| 2주 차 | 회원가입·로그인, 프로젝트·멤버 초대, DB·PHP API 구축 |
| 3주 차 | 업무 CRUD, 칸반, 진행률 요약, 대시보드·일정 화면 |
| 4주 차 | 단일 사용자 보드, 블럭·연결선·펜, 저장·복원 |
| 5주 차 | 공동 편집 통신, 동시 접속·재접속, 권한 검증 |
| 6주 차 | 오류 수정, 사용성 정리, 시나리오 테스트, 발표·시연 준비 |

기간과 인원은 예시이며 실제 수업 일정 및 서버 사용 제한에 따라 축소·조정한다.

# **11\. 시연 시나리오 및 검증 항목**

# **11.1 발표 시연 순서**

① 프로젝트 소유자가 로그인해 프로젝트 생성 → ② 다른 브라우저에서 팀원이 초대로 합류 → ③ 업무 카드를 생성해 담당자·마감일 설정 → ④ Dashboard에서 상태 확인 → ⑤ 두 브라우저가 같은 Board 접속 → ⑥ 한쪽에서 블럭 이동·연결선 추가·펜 그리기 → ⑦ 다른 쪽에 동기화되는지 확인 → ⑧ 새로고침 후 데이터 복원.

# **11.2 최소 인수 테스트**

□ 회원이 아닌 사용자는 비공개 프로젝트·보드에 접근 불가.

□ 초대받은 사용자만 프로젝트 참여 가능하며 역할별 편집 권한 적용.

□ 업무 추가·수정·삭제 후 새로고침하여도 데이터 유지.

□ 보드 블럭·연결선·필기가 재접속 후 같은 위치에서 복원.

□ 두 브라우저가 같은 보드에서 작업할 때 변경사항 동기화.

□ 연결 해제·재접속 후 서버의 최신 상태로 복구.

# **12\. 구현 위험과 대응 방안**

| 위험 요소 | 대응 방안 |
| :---: | :---: |
| 실시간 편집 충돌 | 객체 단위 갱신, 서버 버전값 관리, 재접속 시 상태 재동기화 |
| 펜 이벤트 과다 | 입력 획 묶음 전송, 드래그 이벤트 횟수 제한 |
| DB·UI 구조 변경 비용 | 객체 공통 속성과 확장 필드 분리, API 스키마 사전 합의 |
| 구현 범위 과다 | 회원·프로젝트·업무·보드 저장부터 완성한 후 실시간 연결 |
| 실습 서버 제약 | Node.js 서버 허용 여부 확인, AJAX 폴링 대체안 마련 |

# **13\. 프로젝트 차별성 및 발표 요약**

기존의 목록 중심 프로젝트 관리에서 한 단계 나아가, 업무 카드를 자유롭게 배치하고 서로 연결하며 동시에 손글씨와 아이디어를 기록할 수 있는 시각적 협업 공간을 제공한다.

차별점은 ‘프로젝트 업무 데이터와 화이트보드 객체의 연결’이다.

보드 위 작업 블럭에서 담당자·상태를 바꾸면 일반 업무 목록과 대시보드에도 동일한 정보가 반영되도록 설계한다.

최종 발표 핵심: 웹서버에서 사용자·권한·DB를 관리하고, 여러 브라우저가 공동 보드에서 같은 작업을 실시간으로 완성하는 과정을 시연한다.

# **14\. 결정이 필요한 사항**

□ 실제 팀 인원 및 전체 개발 기간.

□ PHP·MySQL 필수 여부와 Node.js/Socket.IO 병행 가능 여부.

□ 강의실 XAMPP 로컬 시연인지, 별도 배포 서버 사용인지.

□ 실시간 동기화의 필수 수준(즉시 반영 vs 1\~3초 자동 갱신).

□ 모바일 지원 및 파일 업로드 포함 여부.

문서 상태: 팀 프로젝트 주제 선정 및 요구사항 합의를 위한 1차 기획 초안.

# 28일차 — 업무·담당자·마감·체크리스트 SQL 집계

---
## API와 접근 권한

`GET /api/projects/{id}/analytics/summary`

27일차의 회원 결합 세션 또는 기존 독립 게스트 세션과 작업실 viewer 이상 역할이 필요하다. 로그인한 회원도 현재 선택한 게스트의 작업실 권한을 확인한다. 비인증은 401, 다른 작업실은 403이다. 권한 확인 후 필터를 검증한다. 응답은 기존 JSON 형식과 Cache-Control: no-store를 사용한다.

기존 작업실·업무·체크리스트 테이블을 조회하며 DB 구조나 데이터를 변경하지 않는다. 새 제품 의존성도 추가하지 않는다.

---
## 필터 계약

| 쿼리 | 허용 값 | 적용 기준 |
|---|---|---|
| created_from | YYYY-MM-DD | 업무 created_at의 해당 날짜 00:00:00 이상 |
| created_to | YYYY-MM-DD | 업무 created_at의 해당 날짜 23:59:59 이하 |
| status | todo, doing, done | 업무 원본 상태 |
| assignee_id | 정규 양의 정수 또는 unassigned | 담당 guest_id 또는 NULL |

필터를 생략하면 해당 조건을 제한하지 않는다. 여러 조건은 AND로 결합하며 업무·담당자·마감·체크리스트 모두 같은 업무 집합을 사용한다. 날짜는 실제 존재하는 1000~9999년의 날짜만 허용한다. 역순 기간·빈 값·배열·알 수 없는 키·잘못된 상태·정수 범위 초과는 400 INVALID_FILTER이다. 기간은 마감일이나 완료일을 뜻하지 않는다.

저장된 DATETIME은 기존 서비스의 서울 지역 시각을 기준으로 해석한다. DATETIME에는 시간대 정보가 없으므로 다른 시간대로 저장된 외부 DB를 자동 변환하지 않는다. 마감 분류 기준일은 PHP에서 Asia/Seoul로 계산해 SQL에 바인딩하며 DB 서버의 CURDATE 설정에 의존하지 않는다.

---
## 응답 계약

| 필드 | 내용 |
|---|---|
| project_id | 요청한 작업실 ID |
| time_zone, as_of_date | Asia/Seoul, 마감 분류 기준 YYYY-MM-DD |
| filters | 실제 적용한 created_from·created_to·status·assignee_id. 생략 조건은 null |
| tasks | total·todo·doing·done·other·completion_rate |
| assignees | assignee_id·display_name·total·done·completion_rate 배열 |
| due | overdue·today·soon·later·none·closed |
| checklist | total·done·completion_rate |

완료율은 완료 수 / 전체 수 × 100, 소수 첫째 자리 반올림이다. 분모가 0이면 0을 반환한다. 필터 결과가 없으면 모든 건수·비율은 0이고 assignees는 빈 배열이다.

담당자는 이름이 아닌 guest_id로 구분한다. 미배정은 assignee_id: null, display_name: 미배정이다. 실제 선택 업무가 있는 담당자만 반환하며, 정수 ID 오름차순 뒤에 미배정을 배치한다. 현재 멤버가 아니어도 해당 작업실 업무에 남은 담당자는 집계한다. 이름이 같아도 합치지 않는다. 앞으로 차트 화면은 assignee_id를 식별자로 사용하고 이름은 textContent로 출력해야 한다.

허용 상태 이외의 기존 DB 자료는 tasks.other로 집계하여 전체에서 누락시키지 않는다. 다른 상태를 새 업무에 허용하거나 데이터 품질을 자동 보정하는 기능은 추가하지 않는다.

---
## 마감 분류

| 구분 | 조건 |
|---|---|
| none | 마감 없음. 완료 여부 무관 |
| closed | 마감이 있고 상태가 done |
| overdue | 미완료이며 서울 기준 오늘 0시 전 |
| today | 미완료이며 오늘 0시 이상, 내일 0시 미만 |
| soon | 미완료이며 내일 0시 이상, 오늘부터 4일 뒤 0시 미만 |
| later | 미완료이며 오늘부터 4일 뒤 0시 이상 |

분류는 서로 겹치지 않는다. today와 soon을 합하면 오늘부터 3일 이내 마감 업무다. 기존 현황판의 날짜 단위 분류에 맞추며, 완료한 업무는 기한 초과·임박 수에 포함하지 않는다.

---
## 집계 방식

SQL 한 문장에서 tasks를 작업실·필터로 제한하고 담당자별로 COUNT/SUM을 계산한다. task_items는 먼저 해당 작업실의 task_id별 한 행으로 축약한 뒤 LEFT JOIN한다. board_objects를 집계에 조인하지 않으므로 같은 업무를 여러 보드에 배치해도 한 번만 센다. PHP는 SQL의 담당자별 카운터를 더하고 비율과 응답 형식을 구성한다.

모든 지표는 한 SQL 문장의 일관된 읽기 결과다. API에는 통계 캐시가 없으며 다음 요청에서 업무 상태·담당자·마감·항목 수정 및 삭제를 다시 집계한다. 기존 tasks.project_id 외래키 인덱스와 task_items의 task_id 인덱스를 사용하며, 대규모 운영 부하 시험은 이번 로컬 검증에 포함하지 않는다.

## 검증

`node apps/realtime/scripts/test-analytics.js`

실행별 taskcanvas_d28_ 임시 DB와 예약한 PHP 포트를 생성한다. 읽기 전용 서버 식별을 확인한 후에만 가상 회원·작업실·업무를 저장한다. 개발 DB·실제 계정은 수정하지 않고 테스트 프로세스·임시 DB·임시 라우터를 정리한다. DB 생성·삭제 권한이 있는 개발 계정이 필요하다. PHP_BIN과 ANALYTICS_TEST_PORT로 실행 환경을 지정할 수 있다.

2026-10-18, PHP 8.2.12·MariaDB 10.4.32에서 검사 40개 통과. 구현 전 미등록 경로로 권한 검사가 실패하는 것을 확인한 뒤 구현했다. 회원·독립 열람자·다른 작업실 격리, 회원 쿠키 없는 연결 게스트 거부, 빈 결과, 3일 마감 경계, 중복 보드 참조·체크리스트 조인, 필터 교집합·오류, 독립 SQL 결과 비교, 변경·삭제 후 재집계, 기존 알 수 없는 상태 보존, 로그아웃 후 거부를 포함한다.

## 기존 기능 회귀와 함께 수정한 문제

회원 접근·실시간 검사 59개, 기존 회원 인증 41개, 인증 DB 장애 차단 1개를 함께 확인했다. 수정 후 기존 전체 수용 테스트는 자동 28개·보안 2개·운영 1개 통과, 실패 0개, 수동 2개였다. 통계 구현과 감시 경합 수정에 대한 별도 코드 검토에서도 조치할 문제는 없었다. 수용 테스트 도중 작업실 삭제는 성공했으나 삭제 알림이 누락되는 27일차 감시 순서 경쟁을 발견했다. 진단 결과 데이터·파일 정리와 연결 종료는 성공했지만 보드·작업실의 project:deleted 수신이 모두 없었다.

인증 감시가 삭제 감시보다 먼저 무효 연결을 발견한 경우 작업실 존재를 확인하고, 삭제된 작업실이면 기존 project:deleted 계약으로 알린 뒤 해제하도록 보완했다. 인증 조회 장애는 추가 조회 없이 차단하며, 삭제 사유 조회가 실패해도 접근을 허용하지 않는다. 보드 감시를 30초로 늦춘 별도 DB 테스트에서 수정 전 실패·수정 후 통과를 확인했다.
